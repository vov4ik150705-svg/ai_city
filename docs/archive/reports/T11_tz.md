## D1. Кадр аттестации: минута для корня, сутки города для IPFS

Три оси нельзя мешать.

**(а) Период корня в чейне.** Параметр `attest_root_period_s = 60` (`content/params/attest.json`). Батчер просыпается раз в минуту реального времени, собирает **все** запечатанные тики всех городов за эту минуту, строит одно дерево, шлёт один корень.

**(б) Гранулярность IPFS.** Один объект на пару `(city_id, city_day)`. CID публикуется в событии того корня, который закрывает сутки этого города: минута, в дереве которой лежит тик этого города с `hour == 0` после суток `D` (контур полуночи закрывает GDP/Stability суток `D`, см. D4). CID-нагрузка = число городов в сутки, не города × `1440`.

**(в) Ключ группировки.** Дерево минуты — по стенным часам. IPFS-агрегат — по суткам **города**. Ключи обязаны расходиться: `DESIGN.md` §3 даёт каждому аккаунту свой календарь `city_time = anchor + (now − first_login) × rate`. Границы суток разных городов размазаны по реальному времени.

Обоснование, которое уже стоит в `docs/TICK.md` §9: при часовом корне окно «выплачено, но не аттестовано» достигает `3600` с; при минутном — `60` с, в `60` раз меньше, ценой `1440` маленьких транзакций в сутки на L2. Дерево минуты и так собирает работу, потому что сутки городов разнесены. Часовой корень при разнесённых сутках не экономит ничего, кроме числа транзакций.

Что ломается иначе: часовой корень оставляет час неаттестованных выплат; IPFS на каждый тик топит CID; группировка IPFS по стенным часам смешивает чужие сутки города в один объект и ломает реплей §6.3 «батч на сутки города».

**R-T11-1.** Пословная правка `DESIGN.md` §6.2 — готовый текст в `docs/TICK.md` §14. Канон этим шагом не править.

## D3. keccak256 для merkle, sha256 для пака

Развилка уже решена: докстринг `content/pack.py::pack_hash` 86–88 — «Deliberately not keccak … Leaves stay keccak per DESIGN.md 6.2». Канон §6.2 не меняет хеш-функцию листьев. Значит keccak256 появляется как **чистая реализация на Python без зависимостей** в `content/keccak.py` — ровно по той же причине, по которой sha256 выбран для пака: публичный верификатор §6.3 переписывается на любом языке без цепочки пакетов.

Это **Ethereum keccak256**, не SHA3-256 (у SHA3 другой domain padding). Keccak-f[1600], rate `1088` бит = `136` байт, capacity `512`, паддинг `10*1`, выход `32` байта. Алгоритмические константы живут в `keccak.py`, не в экономике; файл **не** входит в L45 (как `fragments.py` / `seasons.py`).

Пин тестовыми векторами (фикстура `content/fixtures/tick_aggregates.json` блок `keccak_vectors` либо константы, которые читает линтер):

- пустая строка → `c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470` (публичный вектор Ethereum);
- `"abc"` как UTF-8 → `4e03657aea45a94fc7d47ba826c8d667c0d1e6e33a64a036ec44f58fa12d6c45`;
- входы длиной ровно `135` / `136` / `137` байт (граница ставки rate=`136`): дайджесты **посчитать реализацией и запинить** в фикстуру; не выдумывать до прогона. Правило L202 падает, если вектор сменился.

Домены хеширования — байт-префикс, иначе лист выдаётся за узел. Префиксные байты — параметры пака (`attest.json`), не литералы в коде:

- `leaf = keccak256(merkle_leaf_domain_byte || canonical_bytes)` с `merkle_leaf_domain_byte = 0`;
- `node = keccak256(merkle_node_domain_byte || left || right)` с `merkle_node_domain_byte = 1`, где `left`/`right` — `32` байта **позиционно**, не сортированная пара (сортировка теряет позицию и допускает двусмысленные доказательства);
- уровень с нечётным числом узлов: последний узел **поднимается на следующий уровень как есть**; дублирование запрещено;
- дерево из одного листа: корень равен этому листу.

**R-T11-11.** `DESIGN.md` §6.2 сейчас: «Лист = keccak(канонические байты)». Стало: доменный префикс. Текст правки — `docs/TICK.md` §14. Канон не править этим шагом.

Что ломается иначе: sha256 на листьях расходится с §6.2 и с уже написанным комментарием в `pack.py`; зависимость `pysha3` ломает «верификатор на любом языке»; сортированная пара и дубликат нечётного узла — классические двусмысленные merkle-доказательства.

## D4. Два контура границы суток, оба остаются

Всё это уже так в `tick.py`. **Ни одна из этих веток не меняет час.**
- **`hour == time.efficiency_recalc_hour` (`6`, `time.json` 58–63).** Пересчёт efficiency района по данным на закрытие предыдущих суток (`DESIGN.md` §4.6, params `efficiency_k_bps = 25000`, `efficiency_clamp_bps = 1500`, `oracle_stale_city_hours = 6`, `oracle_decay_city_hours = 48`, `oracle_decay_bps_per_day = 500` — все уже в `economy.json`); settlement фрагментов (`fragments.settle_hour` → тот же час); settlement сезонов (`seasons.settle_hour` → тот же час). Сейчас ветка в тике пустая — T11 её заводит.

Обоснование: разные физические величины. Храповик привязан к целым суткам города от anchor — внутренние часы. Efficiency привязана к закрытию реального рынка; `DESIGN.md` §3.3 объявляет нестыковку календарей сознательной. Сведение либо сдвинуло бы заморозку бюджета на шесть часов, либо увело бы efficiency с часа, на который уже ссылаются `docs/PRIZES.md` и `fragments.py`.

`city_clock` (`tick.py` 169–178): tick `0` = `12:00` дня `1` (`time.anchor_hour = 12`). Первая заморозка бюджета — в полдень первых суток (`tick_index == 0` или `hour == 0`); первая полночь — на тике `12`. Это не баг, это anchor из `DESIGN.md` §3.

Целочисленный пересчёт E (не float из §4.6):

```
ratio_bps = ema_24h * BPS // max(1, ema_30d)
delta_bps = ratio_bps - BPS
boost_bps = efficiency_k_bps * delta_bps // BPS
efficiency_bps = clamp(BPS + boost_bps, BPS - efficiency_clamp_bps, BPS + efficiency_clamp_bps)
```

Сток оракула (не путать с минтом `STALE_PRICE`): возраст > `oracle_stale_city_hours` → держим последнее, код HUD `STALE` / `ORACLE_STALE`; возраст > `oracle_decay_city_hours` → тянем к нейтрали `BPS` шагом `oracle_decay_bps_per_day` за сутки города (может резать бонус — сход к нейтрали, не «только вниз» рабочего курса минта).

## D5. Личные часы — модель движка; когорта T3 — тестовая проекция

Спека движка работает с `city_time` как с **записанным входом на город**:

```
tick_index = (city_time - city_time_at_tick0) // tick_length_city_hours
```

`tick_index` — производная, не второй источник правды (правило «выводимое не хранится»). `city_time_at_tick0` **не параметр**: это показание часов в момент первого захода = `anchor_hour` на `anchor_day_index` (`12` на дне `1`). Обратная формула, если `city_time` во входах нет:

```
city_time = city_time_at_tick0 + tick_index * tick_length_city_hours
```

`tick()` принимает `city_time` во входах; если ключа нет — выводит из `tick_index`. Для харнесса T3 это тождество: ни одно число не двигается. `sim.price_inputs` сегодня кладёт только `tick_index` (recon §1.1) — оставить совместимость.

Когорта T3 (все города в одной фазе, общий `tick_index`) — **тестовая проекция**, не модель мира. Параметр `sim_cohort_shared_epoch = 1` в `content/params/sim.json` с честным `why`. Переписывать T3 под личные часы в v1 запрещено: это перекалибровка полос T2 ради того, что харнесс и так измеряет корректно (когорта усредняет фазу).

Батчер D1 исходит из личных часов: сутки городов в реальном времени не совпадают. Харнесс — из когорты.

**R-T11-5.** Назвать явно: `DESIGN.md` §3 даёт личные часы, `content/sim.py` считает когорту с общей фазой.

## D7. Агрегаты: Productivity измеряется, Happiness считается, штраф выключен

Новый модуль `content/aggregates.py` — чистые функции над явным входом, фикстура `content/fixtures/tick_aggregates.json`. Когорта T3 агрегаты **не считает**: у неё нет зданий и складов. Это граница харнесса, не дыра.

**Productivity — производная, не множитель.**

```
productivity_bps = realized_output * BPS // max(1, nominal_output)
```

`nominal_output` — выход при нулевом простое и полном фонде (`payroll_ratio_bps = BPS`, не idle). Так `DESIGN.md` §8 «множитель выхода» перестаёт быть вторым множителем поверх цепочки `база × affinity × уровень × дрожь × сплав` и становится измерением этой цепочки. Ноль дрейфа, ноль новых чисел. В `apply_stack` слот стадии `productivity` остаётся тождеством `BPS` (уже так, `build.py` 2408–2410). **R-T11-9:** пословная правка §5.3 шаг 5 и §8.

**Happiness — формула, не слова.** Четыре члена §8, каждый в bps, нейтраль `10000`, веса — авторские параметры в `tick.json`, сумма весов ровно `10000`:

```
housing_bps  = min(10000, housing_capacity * 10000 // max(1, population))
parks_bps    = min(10000, park_slots * park_capacity_per_slot * 10000 // max(1, population))
energy_bps   = min(10000, energy_stock * 10000 // max(1, energy_demand))
payroll_bps  = payroll_ratio_bps
happiness_bps = Σ(w_k * term_k) // 10000
```

Каждый член и результат зажаты в `[0, 10000]`. `park_slots` уже есть: `generated.placement.park_slots` / `world.py` (`1 + open districts`, L182). `park_capacity_per_slot` — авторский параметр; **v в решениях архитектора нет** — назначь с `why` ≥ 24 символов, не копируй `population_per_job` молча как «очевидное». Четыре веса — тоже без назначенного `v`; сумма обязана быть `10000`, линтер ловит иное. Никаких новых счётчиков парков.

**Штраф Happiness → Productivity выключен в v1:** `happiness_penalty_live = 0`, прецедент `season_prizes_live = 0`. Включение умножает выход и сдвигает полосы T2 и весь прогон T3 — балансовое решение, не движковое. Когда включат, штраф входит **строкой в таблицу модификаторов T5** (ключ выхода), не новой веткой кода.

**Пороги HUD 50% и 70%** (`HUD.md` §4.1) сегодня только в тексте интерфейса. Перенос в пак: `happiness_penalty_threshold_bps = 5000`, `stability_hint_threshold_bps = 7000`. `HUD.md` начинает на них ссылаться. **R-T11-7**, пословная правка — `docs/TICK.md` §14, файл `HUD.md` этим шагом не править.

**Stability** — единственное определение: `seasons.stability_bps = valid_ticks * BPS // ticks_per_city_day` (`seasons.py` 126–130). Тик его не переопределяет, а зовёт. Валидный тик — `DESIGN.md` §2.8 и `fragments.tick_accrues`: оплаченная работающая связка, не IDLE/стройка. Второго определения не заводить.

## D8. Догон оффлайна: производственная модель и проекция харнесса

Движок: при заходе `elapsed = (city_time_now - city_time_last_tick) // tick_length_city_hours`; догоняется `min(elapsed, offline_cap_ticks)` тиков **хвостом** (последние N перед текущим моментом). `offline_cap_ticks` **не хранится**: `offline_cap_city_hours_base // tick_length_city_hours` (`time.json` derived, при текущих params `12`). Потолок MSFT поднимает часы, не отдельный счётчик тиков.

Пропущенный промежуток не исчезает молча: одна запись `status = "gap"`, `reason = "IDLE_OFFLINE_CAP_REACHED"`, промежуток `[from_tick, to_tick)`, потому что молчаливого нуля нет (`DESIGN.md` §5.3). `tick_index` остаётся монотонной функцией `city_time`; дыры в нумерации законны и обязаны быть объяснимы записью.

Инвариант, который надо **доказать пробой**, не словами: **догон ≡ реплей.** N тиков, посчитанных догоном за один заход, дают побайтово те же записи, что N тиков по одному онлайн. Одна функция, одни входы. Обёртка `catch_up` в `tick.py` только циклит `tick()` и пишет gap-запись; самой экономики в обёртке нет.


Модель оффлайна в харнессе T3 — квадратная волна `tick_index % login_period` (`_in_offline_window`, `tick.py` 431–443) — **остаётся как есть.** Замена на `last_login` сдвинет измеренный аптайм минималиста (`login_period=24`, cap=`12`) и полосы возврата.

**R-T11-8:** производственная модель и проекция харнесса разные, обе названы.

Догон длиной ноль: `elapsed <= 0` → ни одного тика, gap-записи нет. Догон длиннее потолка: ровно cap тиков хвостом плюс одна gap-запись на префикс.

## D9. Что падает закрыто, а что открыто

Один абзац, который обязан стоять в `docs/TICK.md` §2 и §9.

**Экономика падает закрыто.** Тик отказывается считать на паке, чей хеш не совпал с записанным во входе (`PACK_HASH`, уже `tick.py` 1017–1018). Пустой `pack_hash` во входе сегодня пропускает сверку — для боевого пути запретить: отсутствие хеша = отказ, как ноль фида = минт 0. Харнесс T3 всегда кладёт `cfg["pack_hash"]` (`sim.price_inputs` 224), поэтому инертность не ломается, если сверка остаётся «пустой ключ пропускает» **только** когда ключа нет (совместимость) и «ключ есть и не совпал → отказ». Не вводить второй код.

**Аттестация падает открыто.** Отказ IPFS, RPC или гейта не останавливает выплату (`DESIGN.md` §6.4: «без зарплаты нет записи», не наоборот). Записи копятся в outbox с ретраем; наружу отдаётся `attest_lag_ticks` (derived: непрошедшие в корень запечатанные тики); интерфейс показывает `· logged` вместо `Verified` (`HUD.md` 148, 247). Ни одного `raise` на пути аттестации внутрь `tick()`. Merkle/CID считаются **после** возврата `(state, records)` хостом, не изнутри чистой функции.

Live-отправка корня в чейн в v1 вырезана (`DESIGN.md` §11: merkle+IPFS — v1.1, формат каноничен с первого дня). T11 отдаёт формат, дерево, keccak и outbox; **R-T11-10**.

## D10. Дрожь: `% span` остаётся именованным исключением

`build.tick_jitter_bps` (`build.py` 1191–1202) берёт `prng % span`, `span = 2*w+1`, `w = jitter_width_bps` или половина при Steady (`jitter_width_bps = 500`, `balance.json` 95–100). Генератор мира T10 использует rejection sampling. Менять дрожь нельзя: любое изменение переоценивает каждую уже записанную смену.

Строка в `content/params/exceptions.json` (схема: `entity`, `field`, `why`, `src`; бюджет `meta.exception_budget = 6`, сейчас список пуст — одно исключение влезает):

- `entity`: `tick_jitter_bps`
- `field`: `remainder_mod_span`
- `src`: `DESIGN.md §5.3`, `content/build.py` `tick_jitter_bps`
- `why`: смена на rejection переоценивает записанные смены; 64-битный prng, относительное смещение не превышает `(2**64 % span) / 2**64`; новый код выборок обязан использовать rejection; исключение только на существующую дрожь.

Линтер L223 **считает** `2**64 % span` и проверяет, что в `why` или в derived-свидетеле названа эта граница, и что `span = 2*w+1` с `w` из params. Число смещения в прозе TICK.md не писать — формула и правило.

## D11. PRNG

Канон `DESIGN.md` §5.3: `hash(city_id, tick_index, agent_id)`. Факт кода: `sha256(f"{city_id}:{tick_index}:{agent_id}").digest()[:8]`, big-endian (`build.JITTER_SEED_FMT`, `tick.seeded_prng`). T11 фиксирует это как канон движка и добавляет **доменный стрим**.

Интерпретация «пустой стрим воспроизводит сегодняшнюю строку байт в байт», обязательная, иначе формат `f"...:{stream}"` с пустым stream даёт **хвостовое двоеточие** и ломает все записанные смены:

```
if stream:
    msg = f"{city_id}:{tick_index}:{agent_id}:{stream}"
else:
    msg = f"{city_id}:{tick_index}:{agent_id}"
```

Пустой стрим — единственный, который обязателен в таблице пака для дрожи. Другие стримы не заводить, пока им нет вызова в T11 (мир T10 живёт в `world_prng`, не здесь). Список допустимых стримов — таблица в `tick.json` (или `attest.json`), не строковые литералы по коду. `seeded_prng` принимает `stream=""`.

Pending-строку переформулировать: owner сдвигается на T12 для **сервиса** сэмплера; T11 закрывает харнесс-сценарий. Why новой формулировки обязан сослаться на R-T3-20 и на то, что калибровка заморожена. Два долга проводки (`fragment_tick_wiring`, `season_tick_wiring`) удаляются из `pending.items` только после того, как соответствующие вызовы стоят в `tick.py` и правила L219–L221 зелёные.

## D12. Сэмплер и `sampler_corp_eth_endogenous`

Сэмплер живёт снаружи тика (T12), но T11 задаёт **контракт входа**: TWAP снимается по фиксированным шагам `city_time`, кладётся во вход тика вместе с `price_sample_city_time`; тик наружу не ходит никогда (`open` / `socket` / HTTP в AST тика запрещены).
