## Четыре дефекта, что казалось находкой

1. **Глобальный лимит банка.** R-T3-18 утверждал инверсию полос (min 4980–7280, opt ~100). Подозрение: FIFO по алфавиту `minimalist` раньше `optimizer`. В коде уже был `scale_bps`, но `cap_burn` шёл от полного want без личного капа, `got // weight` обнулял мелкую выдачу, а реинвест 2000 bps применялся к **остатку** `earned_left` каждый тик: `(8000/10000)^24 ≈ 47` bps остатка за сутки — отсюда «оптимизатор голодает». Починка: `issued_i = ask_i × cap / Σ`, личный предел до пропорции; реинвест = доля **потока** `payout`. После: low min 2928 / opt 7278. **R-T3-18 снят.**
2. **N_min подгонкой.** Fit с якорем N=1 дал 246 / 1882 / 1647 и инверсию хайпа. Бисекция полных сезонов: 229 / 705 / 1057, монотонно. **R-T3-19 снят.**
3. **A_∞ по сценариям.** Fit 14627 / 15203 / 14645 (mid > hype) — шум якоря N=1, где cork глушит каплю. При n_hi=400000: 13986 / 13986 / 13988. Остаток **2 bps**.
4. **R-T3-17 без лечащего числа.** Калибровка min 2837 < 3500. Чувствительность: `offline_cap=24` → 5812 (пол пройден, потолок 4500 пробит); `residual_idle=0` и `bank_level_gain=10000` → 2841, не двигают; пол полосы = 2841 — сдвиг цели. **Числом при аптайме 4750 не лечится.** Расхождение с целью T2. `plus_day` пуст.

## Отношение возвратов vs аптайм

Измерено 8213/2837 → **28949 bps** против канонных 2:1 = **20000 bps**. Остаток **8949 bps**. Если бы отношение было 2:1 от opt, min был бы 4106 и в полосе. Причина числом: глобальный 1% взвешен по запросу, когорта с большим капиталом забирает большую долю.

## Адверсариал третьего захода

1. Две когорты, равные запросы, имена aaa/zzz и zzz/aaa, обратная вставка → withdrawn побайтно совпал ✔
2. FIFO [cap, 0] на равных asks → L55 ✔
3. N_min(hype) < N_min(mid) → RuntimeError; на прогоне 1057 ≥ 705 ✔
4. A_∞ mid < A_∞ low более чем на 1 bps → RuntimeError; на прогоне 13986 ≤ 13986 ≤ 13988 ✔
5. Реинвест 100%: A_gross растёт, измеренный возврат не растёт ✔

## Чеклист дыр
