## §0. Предусловие фазы

До первой правки проверить командой, а не памятью:

```
python content/build.py            # pack 53, hash 411900ef…7b87, круг 1445
python content/lint.py             # 304 / 0
```

и прочитать `content/params/launch.json` поле `deployed`.

- Все пять полей `deployed` пустые → фаза стартует с `P0`.
- Хоть одно заполнено, или в чейне есть наш `TokenLaunched` → **остановиться и спросить владельца**. Ставка уже снята навсегда; тогда `P7` не «подписать», а «сверить факт с паком», и `P3` теряет право менять контракты, уже стоящие в мейннете.

Второе предусловие: `M7_final.md` лежит на диске и его гейт зелёный. Третье: владелец назвал числа из §9, без которых `P3` и `P7` не закрываются (`pause_ready_delay`, адреса `studio_eth_recipient` / `guardian` / `signer`). Четвёртое: картинка V0–V12 закрыта (`V12_final.md`); клеточный кадр v3 закрыт (`V3-7_final.md`, `PLAN_VISUAL_V3.md` — архив). Живой 3D-остров до `P7` — `docs/reports/PLAN_ISLAND.md`. `P7` не начинается без решения владельца (`R-V-76`).

## §1. Что фаза делает и чего не делает

**Делает.** Превращает зелёный репозиторий в работающий продукт: закрывает дыру идентичности, заводит два трека CI, проводит аудит контрактов, собирает настоящий продакшн-образ, репетирует полный цикл времени и транспорта, поднимает наблюдение и дежурство, подписывает `launchToken`, разворачивает пять контрактов в мейннете и доводит первый цикл до фактической выплаты игроку.


**Не переоткрывается.** Вариант A компенсации трения (владелец, 2026-08-30). Rev-A целиком: шесть активов месяца, `1.0 / 0.8 / 0.2`, десятка трат в фарм, пятая группа контрактов, vault как предохранитель, HUD без кнопок слива.

## §2. Разведка: что найдено в дереве на входе фазы

Факты, установленные чтением кода, а не предположением. Каждый — вход этапа.

| находка | где | следствие |
|---|---|---|
| Мутирующая команда не проверяет владение. `city_id` берётся из **тела запроса**, ответ выдаётся кому угодно | `services/api/src/commands.ts` строки чтения `obj["city_id"]` | `R-P-1`, этап `P1`. На проде это «потратить чужой Capital, зная его `city_id`» |
| `API_UNAUTHORIZED` объявлен в `codes.json` и разложен в HTTP 401, но **не выдаётся ни одной веткой** | `services/api/src/envelope.ts` `transportStatus` | Новый код заводить не нужно: форма готова, реализации нет |
| Лимит команд живёт в памяти процесса, ключ — `city_id` из тела | `commands.ts` `rates: { [cityId]: RateGate }` | `R-P-2`. Рестарт обнуляет лимит; две реплики делят его надвое; выдуманные `city_id` растят словарь |

| Dockerfile копирует только `dist` пяти сервисов: ни `node_modules`, ни пака | `deploy/Dockerfile` | Образ не запускается. Этап `P4` |

| CI существует как список шагов, но нет ни одного запускающего его файла | `scripts/ci.mjs`, `.github/` отсутствует | Этап `P2`. Ночного прогона нет — отсюда и соблазн гонять `--jobs 8` на каждом шаге |
| У контрактов нет скрипта деплоя и нет аудита | `contracts/src` пять `.sol`, `contracts/test` два `.t.sol`, `script/` нет | Этап `P3` и `P7` |

## §3. Решения `D-P-1` … `D-P-13`

### `D-P-1`. Фаза называется P, этапов девять, фазовое правило одно

Ключи roadmap: `release_form`, `player_identity`, `ci_tracks`, `contract_audit`, `prod_image`, `time_rehearsal`, `ops_watch`, `mainnet_launch`, `season_one`. Ровно девять, десятый не выдумывать, `owner_drain`-класса имён не заводить.

`.cursor/rules/code-phase.mdc` **переписывается** под фазу P. Второй `.mdc` про этапы не заводится — `R-L-16` остаётся в силе, и файл сохраняет историческое имя ровно так же, как папка `ai_city`.

Причина: без строк roadmap любой новый `it()` роняет `L268`, а любой новый этап рождает второй список этапов. Это ровно тот же механизм, что `R-M-1`.

### `D-P-2`. Точка невозврата — `P7`, и раньше неё нет ни одной необратимой операции

До `P7` не подписывается `launchToken`, не деплоится ни один контракт в мейннет, не принимается ни один реальный депозит. Всё, что делают `P0`–`P6`, откатывается удалением ветки. Клеточный кадр (`PLAN_VISUAL_V3`) закрыт; перед `P7` ещё живой остров `PLAN_ISLAND.md`. `mainnet_launch` — после решения владельца, не из фазы острова.

Причина: `creator_tax_bps` замораживается подписью навсегда (`docs/LAUNCH.md` §8). Аудит после подписи — это аудит того, что уже нельзя починить.

### `D-P-3`. Идентичность: подпись владения адресом → серверная сессия; новых кодов транспорта не заводить

Поток:

1. `POST /auth/nonce` с телом `{address}` → `{nonce, expires_city_time}`. Nonce одноразовый, живёт в таблице, срок — производный.
2. Клиент подписывает **каноническое сообщение**: домен, адрес, nonce, `pack_hash`, срок. Байты сообщения собираются по правилу из пака, а не форматированием строки в клиенте.
3. `POST /auth/session` с телом `{address, nonce, signature}` → сервер восстанавливает адрес из подписи, сверяет с заявленным, гасит nonce, выдаёт непрозрачный `session_id`.
4. Мутирующая команда несёт `session_id` в заголовке `Authorization`. `city_id` берётся **из сессии**. Поле `city_id` из тела команды исчезает.
5. Нет сессии, истекла, или тело называет чужой город → `API_UNAUTHORIZED`, HTTP 401. Код уже есть.

Чтение остаётся публичным: `GET /city/{city_id}/state`, `GET /pack/{hash}`, `GET /ready` и сокет чтения сессии не требуют. Причина: публичная проверка записей — цель канона (`DESIGN.md` §6.3), и закрывать её ради симметрии значит ломать заявленное свойство. Граница простая: **читает кто угодно, пишет только владелец**.

Демо-аккаунт получает сессию без адреса: `account_kind = demo`, субъект — серверный непрозрачный идентификатор. Барьер демо не ослабляется ни на байт: `demo_transfer_edges` остаётся пустым, `L112` и `L292` не трогаются.

`session_ttl_s` — **производная**, не хранимое число: длина суток города в реальных секундах. Хранить «24 часа» — дефект класса `L09`/`L281`. Причина выбора: сессия не должна переживать суточный цикл бюджета фонда, в котором она открыта.

Два новых маршрута появляются строкой в `api.path_rules`, а не веткой в `http.ts`. Множество `POST /command/*` по-прежнему равно множеству `commit:*` — биекция `L232` не ослабляется, потому что `auth` не команда.

### `D-P-4`. `city_id` непрозрачен, привязка адреса живёт вне тика, сид острова записывается при создании

`city_id` — серверный случайный идентификатор, выданный один раз. Связь `address → city_id` лежит в транспортной таблице. Сид генерации острова вычисляется из аккаунта один раз при создании города и **записывается в строку города** как обычный вход.

Что запрещено прямо: адрес игрока, `session_id` и любое поле идентичности не входят ни в `DecisionRecord`, ни в заголовок тика, ни в `record_field_homes`. `layout v1` не двигается, `python content/vectors.py` после `P1` даёт **тот же** sha256.

Причины три. Реплей старого города не должен зависеть от текущей привязки кошелька. Смена кошелька не должна форкать остров. И `hash(city_id, tick_index, agent_id)` — путь PRNG: сделать `city_id` производным от адреса значит впустить адрес в детерминизм тика через чёрный ход.

### `D-P-5`. Лимит команд хранится в БД по субъекту сессии

Ключ — `(city_id, tick_index)`, счётчик инкрементируется атомарно, значение потолка по-прежнему производное `2 × slots_cap` (`L250` не трогается). Счётчик в памяти процесса запрещён правилом.

Причина: `R-P-2`. Хранимый счётчик переживает рестарт, работает на двух репликах и не растёт от выдуманных идентификаторов, потому что субъект теперь не из тела.

### `D-P-6`. Два трека CI, и полный прогон живёт только в ночном

**Шаговый трек** (на каждый push): `python content/lint.py`, `python content/build.py`, `python content/codegen.py --check`, `python content/vectors.py`, `pnpm -w install --frozen-lockfile`, `pnpm -w run gate`.

**Ночной трек** (по расписанию, и на публикации пака): всё из шагового плюс `python content/attack.py --jobs 8`, `python content/sim.py`, `forge test`, сборка образа и smoke прод-профиля.

Файл workflow — **сгенерированный артефакт** из `arch.ci_steps`; ручная правка красная через `codegen.py --check`.

Причина, по которой это отдельное решение, а не деталь: полный прогон атак — 750 секунд, и когда его нет в ночном расписании, он расползается в шаговый гейт и съедает час на каждом шаге. Дисциплина шага держится не уговором, а тем, что регрессия реально гоняется ночью.

### `D-P-7`. Аудит контрактов: внутренний проход обязателен, внешний — решение владельца, но до `P7`

Внутренний проход обязателен и состоит из: инвариантного и фаззинг-набора `forge`, статического анализа, ручного чеклиста интеграции токенов и разбора каждой находки до статуса.

Отдельно и обязательно — **нестандартные ERC-20**. Стоки в казне призов и в стейк-реестре приходят снаружи: у одного нет возвращаемого значения у `transfer`, у другого комиссия на переводе, у третьего `decimals` не 18. Учёт ведётся по **фактической разнице баланса до и после**, а не по запрошенной сумме, и результат вызова проверяется всегда.

Причина: обещанная игроку нарезка, посчитанная от запрошенной суммы, при комиссии на переводе больше того, что реально лежит в казне. Это `PRIZE_CLAIM_UNCOVERED` на ровном месте и на живых деньгах.

### `D-P-8`. Продакшн-образ собирается, а не монтируется

Образ содержит собранный `dist`, продакшн-зависимости и **пак, вшитый по хешу**. Прод-профиль не монтирует репозиторий. Пользователь не root. У каждого сервиса healthcheck, политика перезапуска и лимиты. Миграции — отдельный одноразовый job, выкатывается **раньше** кода. Клиент — статика с иммутабельным кешем по хешу пака и заголовками безопасности.

Тик имеет **единственного писателя**: планировщик берёт блокировку в БД и отпускает её при остановке; реплика без блокировки обслуживает запросы и не тикает.

Причина: `R-P-3` и `R-P-4`. Сегодня прод — это dev с другим именем профиля, а две реплики удвоили бы город.

### `D-P-9`. Репетиция раздвоена: ускоренное время на локальной цепи, реальный темп на тестовой сети

**Прогон А — механика.** Локальная цепь, город прогоняется на 90 суток вперёд так быстро, как позволяет БД. Проверяются границы: окно фарма 14 суток, призовой период 30 суток, сезон 90 суток, снапшот на границе суток, догон ≡ реплей, пропорциональное урезание фонда, обе ноги конвейера, клейм по каждому активу.

**Прогон Б — транспорт.** Тестовая сеть, реальный RPC, реальный пиннинг IPFS, реальный темп, не менее трёх реальных суток. Проверяется не арифметика, а поведение внешнего мира: молчание RPC, устаревший сэмпл, нехватка газа, коллизия nonce, реорг, отказ пиннинга, отказ провайдера LLM. Ни один из этих отказов не имеет права остановить тик.

**Ускорение — это темп вызова тика, и только он.** `city_day_real_hours`, `ticks_per_city_day` и любой другой параметр времени в паке не трогаются; хеш пака репетиции равен хешу пака прода. Причина: 30 суток города — это 750 реальных часов, ждать месяц нельзя, а «ускорить», сжав сутки в паке, значит репетировать другую экономику: поедут `workshop_cost_l1`, вся балансная таблица и печать `build.py`.

### `D-P-10`. Метрика наблюдается измерением, а не порогом

`observed` каждой из десяти метрик — величина, снятая с состояния или из запроса к БД. `observedFromThresholds` остаётся помощником тестов, и его импорт вне тестов красный.

Порог по-прежнему берётся из источника, названного в паке; литерал порога запрещён (`L259` не ослабляется). У каждой метрики появляется канал уведомления. Алерт возраста сэмпла срабатывает раньше, чем устаревание режет курс, — это уже записано в `ARCHITECTURE.md` §8 и теперь становится проверяемым.

Причина: `R-P-5`. Наблюдение, равное порогу, — это десять зелёных лампочек, не подключённых к проводам.

### `D-P-11`. Откатывается образ, пак не откатывается

Опубликованный пак неизменяем. Инцидент лечится предыдущим образом с его собственным вшитым хешем. Миграции только вперёд, аддитивные, выкатываются раньше кода, чтобы старый код пережил новую схему.

Причина: `pack_hash` стоит в заголовке тика. Откат пака после того, как на нём записаны смены, форкает байты и убивает `догон ≡ реплей`.

### `D-P-12`. Порядок мейннета фиксирован и проверяется

`launchToken` (ставка 200, покупка 0) → адрес токена → `Vault` с этим адресом → `StakeRegistry`, `MerkleRoots`, `PrizeTreasury` → запись адресов в env хоста → снятие паузы депозитов. Это **player-ready**, потолок **20 минут** (`D-P-14`). Вечером той же даты, не на этом пути: верификация исходников, `launch.deployed` / `chain.deployed` целиком одной правкой, сид/graduation по `docs/LAUNCH.md`, публикация пака с `--jobs 8` и `sim.py`. Прод-стек к шагу 2 уже крутится, депозиты закрыты; новый образ не собирается.

`chain.deployed` заполняется **целиком или никак** — та же форма, что `L279` держит для `launch.deployed`. Адрес vault-токена обязан совпадать с `launch.deployed.token`.

Причина: Vault принимает адрес `$CORP` конструктором, значит токен существует раньше. Частично заполненный блок адресов — это состояние, в котором половина системы говорит с мейннетом, а половина с пустотой. Пересборка пака и полный прогон на пути игрока раздувают часы из CI, не из чейна.

### `D-P-13`. `rules_version` в фазе P не двигается

Остаётся `0.20.0` (факт G0; водяной знак призов 19 не двигается). Фаза не меняет правил генерации контента: идентичность, CI, образ, наблюдение и деплой не порождают ни одной новой сущности пака через генератор. `pack_version` растёт по `CONTENT.md` §5 на каждом этапе, который правил пак.

Если исполнитель считает, что его правка требует подъёма `rules_version`, — это `R-P-*` к владельцу до правки, а не тихий инкремент. Причина: `prize_live_min_rules_minor` = 19 привязан к выплате призов; сдвиг минора без пересчёта — молчаливая остановка выплат.

### `D-P-14`. Player-ready после токена ≤ 20 минут; пак — вечером

Между `launchToken` и первым депозитом только: сверка `creatorTaxBps() = 200`, четыре деплоя скриптом `contracts/script/PlayerReady.s.sol`, запись адресов в env, `CORPORATOR_DEPOSITS_OPEN=1`. Хост читает адреса из env, не из нового `pack_hash`. Четыре контракта в мейннет до токена не ставятся.

Не на этом пути: эксплорер, `pack_version`, `--jobs 8`, `sim.py`, сборка образа, сид пула, graduation. Полный прогон остаётся гейтом **публикации пака** тем же вечером.

Причина: владелец. Часы CI на критическом пути после токена не являются физикой чейна.

## §4. Этапы `P0` … `P8`

У каждого этапа десять полей. Ни одно не игнорируется. Критерий готовности выполняется буквально, командой, а не рассуждением.

Порядок строгий: `P(N+1)` не начинается, пока гейт `P(N)` не зелёный и `P<N>_final.md` не написан. **Единственное исключение**: если владелец заказал внешний аудит и `P3` ждёт подрядчика календарно, `P4` разрешено вести в это ожидание. `P5` требует обоих зелёными.

6. **Заморозка аргументов конструкторов**: страж, подписант, задержка `pauseReadyAt`, адрес токена. Число задержки — от владельца (§9), не выдумывать.

### `P5` — `time_rehearsal`. Репетиция: механика на ускоренном времени, транспорт в реальном темпе

**Цель.** Полный цикл прожит целиком до первой выплаты — на локальной цепи по времени и на тестовой сети по транспорту, на том самом образе и том самом паке.

**Строка ROADMAP.**
`time_rehearsal` · goal: `Ninety city days on a local chain and three real days on a testnet, same image, same pack hash` · gate_cmd: `python content/lint.py && python content/vectors.py && python content/attack.py --only L285,L286,L291,L292,L304,L325` · ts_gate_cmd: `pnpm -w run gate` · tests: `L285`, `L286`, `L291`, `L292`, `L304`, `L325` · construction_tests: `rehearsal_pack_hash_equals_prod`, `farm_window_settles_at_fourteen`, `prize_period_settles_at_thirty`, `chain_silence_does_not_block_tick` · invariants: `catchup_eq_replay`, `tick_pure`, `demo_isolated` · src: `D-P-9, PLAN_RELEASE P5` · why: `A month of real waiting is impossible and compressing the city day would rehearse a different economy`.

**Входы.** Образ из `P4`, аудированные контракты из `P3`, `content/sim.py` как оракул ожиданий, `GATE_PERF.md` как источник бюджетов.

**Что делать конкретно.**

*Прогон А, механика.* Локальная цепь, контракты развёрнуты, драйвер вызывает тик подряд, не по расписанию. Наблюдаемые границы: 14 суток — закрытие окна фарма и выплата по талонам маяка; 30 суток — закрытие призового периода и Zipf по шести активам; 90 суток — конец сезона; каждая граница суток — снапшот. Снять и приложить числами: `payroll_ratio` по дням, состав корзины, доля студии, пыль в леджерах, `PRIZE_SHARE_CAPPED` при срабатывании капа, хвост от снапшота против полного реплея.

*Прогон Б, транспорт.* Тестовая сеть, реальный темп, не менее трёх реальных суток. Инъекции отказов по одной: RPC молчит; RPC врёт числом вместо hex; фид устарел; газа не хватает; nonce занят; реорг откатывает hop; пиннинг IPFS не отвечает; провайдер LLM отказал. По каждой — ожидание одно: тик не остановился, деньги не выплачены дважды, метрика лага выросла, код деградации выдан.

*Идемпотентность внешнего мира.* Повтор hop после реорга не платит второй раз: ключ операции — идентификатор транзакции, а не порядковый номер попытки.

**Выходы.** `docs/reports/P5_rehearsal.md` с числами обоих прогонов; правило `L325`; четыре пробы; закрытые дефекты, найденные прогоном.

**Критерий готовности.** Обе программы прогонов выполнены; хеш пака репетиции равен продовому; `vectors.py` даёт неизменный sha256; каждый инжектированный отказ показан с реакцией; перф внутри бюджетов `GATE_PERF.md`; `L325` красный при попытке сжать `city_day_real_hours`.

**Объём.** Крупный по времени, средний по коду: драйвер прогона, инъекции отказов, отчёт.

**Зависит от.** `P3` и `P4`.

**Риски.** Соблазн «ускорить» правкой параметра времени — прямой путь репетировать другую экономику. Соблазн засчитать прогон А за прогон Б: локальная цепь не врёт, не молчит и не делает реорг, а именно это и есть предмет проверки. Тестовая сеть с пустым пулом даёт нереалистичное проскальзывание — это ограничение назвать, а не спрятать.

### `P7` — `mainnet_launch`. Подпись, деплой, адреса, публикация

**Цель.** Точка невозврата пройдена в правильном порядке; депозиты открыты за ≤20 минут после токена; вечером адреса в паке фактом.

**Порядок, который нельзя менять.**

*Утро, до токена.* Сухой прогон скрипта на форке мейннета: те же байты, те же аргументы, тот же порядок. Прод крутится, депозиты закрыты. `--jobs 8` зелёный на паке с пустым `deployed`.

*Player-ready (≤20 мин после токена).*

1. `launchToken`: ставка 200, доля покупки 0. Ни одной покупки на лаунче.
2. Прочитать `creatorTaxBps()` живой кривой и сверить с паком. Не совпало — стоп, дальше не идти.
3. `forge script` `PlayerReady.s.sol`: `Vault` с адресом токена, затем `StakeRegistry`, `MerkleRoots`, `PrizeTreasury`. В мейннет до токена не деплоить.
4. Записать адреса в env хоста. `CORPORATOR_DEPOSITS_OPEN=1`. Игрок покупает на кривой и депозитит.

*Вечер, не на пути игрока.*

5. Верифицировать исходники на эксплорере — все пять.
6. Записать `launch.deployed` (пять полей) и `chain.deployed` (четыре адреса) **целиком, одной правкой**.
7. Сид / graduation по `docs/LAUNCH.md` — когда рынок донесёт, не в эти 20 минут.
8. Публикация пака: `pack_version` +1, полный прогон `python content/attack.py --jobs 8` и `python content/sim.py` — это публикация, здесь полный прогон обязателен.
9. Образ не пересобирается: хеш пака вечером меняется только для новых тиков после публикации; хост к шагу 4 уже читал env.

**Выходы.** Депозиты открыты; заполненные блоки адресов вечером; `docs/reports/P7_final.md` с хешами транзакций и временем player-ready; опубликованный пак.

**Критерий готовности.** Player-ready ≤20 мин от чека `launchToken` до `CORPORATOR_DEPOSITS_OPEN=1`; `creatorTaxBps()` живой кривой равен 200; `L279` и `L328` зелёные на полном заполнении вечером и красные на частичном; `L24` зелёный; круг по-прежнему `1445` в полосе `[1400, 1600]`, вход `200` < выход `910`; полный прогон атак и `sim.py` зелёные вечером и приложены числами.

**Объём.** Малый по коду, максимальный по цене ошибки.

**Зависит от.** `P3`, `P4`, `P5`, `P6` — все зелёные, без исключений.

**Риски.** Ставка замораживается навсегда — `A-19` живёт до последней секунды этого этапа. Частично заполненный блок адресов. Адрес токена в конструкторе Vault, отличный от запущенного. Ключ деплоя, оказавшийся в логе CI. `--jobs 8` на пути игрока — `A-P-26`.
