## §1. Что строим и чем это не является

Строим слой рендера изометрического города на PixiJS 8.20.1 (версия пинится
`arch.toolchain`, не поднимается в этой фазе).

Пять слоёв в порядке вывода, снизу вверх:

```
0  sky          небо и облака под островом, тонировка фазы
1  water        анимированная вода, мелкая и глубокая
2  shadow_land  тень острова, смещённая от силуэта
3  ground       чанки земли: трава, бетон, тротуар, дорога, площадь + утёс + берег
4  shadow_obj   тени объектов ромбами футпринта
5  sprites      здания, декор, юниты — порядок художника
6  emissive     свечение: окна, вывески, фонари, фары
7  overlays     пипы уровня, бейджи состояния, подсветка футпринта, выбор
8  labels       подписи зданий битмап-шрифтом
9  fx           попапы тика, прогресс стройки
--- финальный проход ---
10 snap         защёлкивание кадра на палитру
```

Слои 0–9 рисуются в `RenderTexture` размера безопасного прямоугольника, затем слой 10
выводит её на канвас. Без слоя 10 фаза выхода не принимается: он единственный гарант
инварианта палитры (`D-V-3`).

**Чем это не является.** Не 3D. Не физика. Не система частиц общего назначения. Не
редактор. Спрайты не вращаются (`docs/WORLD.md` §2, `L173`). Сглаживание выключено везде:
`antialias: false`, `scaleMode: 'nearest'`, `roundPixels: true`.

## §2. Геометрия — единственная формула, обе стороны

Здесь закрывается расхождение **R-V-10**. Сегодня клиент и эталон трактуют одну формулу
по-разному, и на ромбах это не видно, а на спрайтах даст сдвиг на полтайла.

Константы берутся из пака: `tile_w` из манифеста атласа, `tile_h = tile_w / 2`,
`half_w = tile_w / 2`, `quarter_h = tile_h / 2`.

**Точка отсчёта тайла** (совпадает с `scene.py:tile_origin`, левый верхний угол AABB
ромба):

```
originX(tx, ty) = (tx - ty) * half_w
originY(tx, ty) = (tx + ty) * quarter_h
```

**Центр ромба тайла:**

```
centerX = originX + half_w
centerY = originY + quarter_h
```

**Передний (нижний) угол футпринта `cols × rows`** — точка якоря спрайта, совпадает с
`scene.py:front_vertex`:

```
frontX(tx, ty, cols, rows) = originX(tx + cols - 1, ty + rows - 1) + half_w
frontY(tx, ty, cols, rows) = originY(tx + cols - 1, ty + rows - 1) + tile_h
```

**Позиция спрайта:** `(frontX - anchorX, frontY - anchorY)`, где `anchor` — из манифеста
атласа (нижняя середина спрайта после обрезки).

**Глубина для порядка художника** (совпадает с `scene.py`):

```
depth = (tx + cols - 1) + (ty + rows - 1)
tie   = tx
```

Сортировка стабильная по `(depth, tie, id)`. Третий ключ добавлен против нестабильности
сортировки при равных первых двух — эталон полагается на порядок входного массива,
рендер обязан быть от него независим.

**Обратное преобразование, экран → тайл** (для клика). Даётся точно, потому что
«примерно» здесь даёт промах на границе ромба:

```
// px, py — координаты в мировом пространстве до масштаба камеры
a = px / half_w
b = py / quarter_h
tx = floor((a + b) / 2)
ty = floor((b - a) / 2)
```

Затем проверка попадания в ромб: если точка вне ромба выбранного тайла, берётся сосед по
знаку остатка. Тест `click_maps_to_tile` обязан проверить четыре угла ромба и центр на
всех уровнях зума.

**Функция `apps/client/src/iso.ts:isoProject` переписывается**: она возвращает `origin`,
а не центр, имя меняется на `tileOrigin`, и рядом появляются `tileCenter` и `frontVertex`.
Существующие вызовы правятся. Тип остаётся на `bigint` — координаты тайлов приходят из
пака целыми.

## §3. Атлас — этап V1

Скрипт `art/pipeline/atlas.py`. Stdlib плюс PIL (уже в `requirements.txt`).
Детерминизм — требование, не пожелание.

### 3.1. Вход

- `art/out/*.png` — 33 спрайта, палитра, обводка, обрезка уже применены `pixelize.py`.
- `art/out/tiles/*.png` — 3 вида земли, 15 вариантов дороги, 2 атласа воды 512×256.
- `art/out/sprites.json` — `tile_w`, `sprites[id] = {file, footprint, size, anchor}`.
- `art/palette/corporator.hex` — 53 цвета, 10 рамп.

### 3.2. Выход

| файл | что |
|---|---|
| `art/out/atlas/city.png` | видимый RGBA-атлас, страницы `atlas_page_px` |
| `art/out/atlas/city_index.png` | индексный атлас: R = индекс палитры, G = свечение, B = 0, A = альфа |
| `art/out/atlas/city.json` | манифест: страницы, кадры, якоря, футпринты, хеши |
| `art/out/atlas/lut_phases.png` | LUT фаз: ширина 64, высота = число фаз |
| `art/out/atlas/lut_snap.png` | 3D-LUT защёлкивания палитры, 512×64 |
| `art/out/atlas/atlas.sha256` | sha256 конкатенации канонических байт всех выходов |

### 3.3. Упаковка — детерминированная

Алгоритм: shelf-упаковка по убыванию высоты, при равной высоте — по возрастанию id
(лексикографически, байтами UTF-8). Ни одного обращения к порядку обхода каталога:
список id строится сортировкой ключей манифеста. Отступ между кадрами
`render.atlas_padding_px`, отступ от края страницы тот же. Отступ обязателен: при
`nearest` без него сосед подтекает в кадр на дробном масштабе.

Ограничение страницы `render.atlas_page_px` = 2048 — гарантированный минимум WebGL2.
Если контент не влез — вторая страница, не увеличение стороны.

### 3.4. Индексный атлас — сердце света

Для каждого пикселя видимого атласа:

- **R** = индекс цвета в палитре, `0..52`, записанный как `index` (не нормализованный:
  шейдер читает `texture.r * 255.0` и округляет). Пиксель, не совпавший ни с одним цветом
  палитры, — ошибка сборки, а не приближение: `atlas.py` падает с именем файла и
  координатой. Это тот же замок, что `L332`.
- **G** = интенсивность свечения, `0..255`. Значение назначается не на глаз, а правилом:

| источник свечения | G | как определяется |
|---|---:|---|
| не светится | 0 | по умолчанию |
| окно жилое / офисное | 200 | пиксель принадлежит рампе `amber` **и** окружён рампами `concrete`/`steel`/`navy` со всех четырёх сторон |
| вывеска, логотип, тикер | 255 | пиксель принадлежит рампе района и лежит в маске вывески из `assets.json` |
| фонарь, фара | 255 | id ассета входит в `render.emissive_ids` |
| свет уровня (оверлей) | 200 | пиксели оверлея уровня из `derived.level_overlays` |

Правило окна написано так, чтобы его можно было проверить: тест
`atlas_has_no_foreign_color` заодно проверяет, что у каждого здания с рампой `amber`
есть хотя бы один пиксель с `G > 0`, иначе ночью город будет тёмным.

- **B** = 0, резерв.
- **A** = альфа видимого атласа, один к одному.

### 3.5. LUT фаз

Текстура шириной 64 (53 занято, остальное — нули), высотой = число фаз в
`generated.placement.phases` (сейчас 4, порядок — как в паке: `dawn`, `day`, `dusk`, `night`).

Строка фазы `p`, столбец `i` = цвет палитры `i`, перекрашенный под фазу:

```
tint = ramp_color(phases[p].tint_ramp, представитель рампы)
a    = phases[p].tint_alpha_bps / 10000
mixed = round(palette[i] * (1 - a) + tint * a)
out[p][i] = nearest_palette_color(mixed)
```

Последний шаг обязателен: результат смешивания снова защёлкивается на палитру, поэтому
LUT содержит только цвета палитры и `L331` держится уже на уровне данных.
`nearest_palette_color` — redmean, та же функция, что в `pixelize.py`; вынести в общий
модуль `art/pipeline/palette.py`, не копировать.

Представитель рампы для тонировки — средний по светимости цвет рампы; правило записать в
`why` параметра, чтобы не спорить об этом второй раз.

### 3.6. LUT защёлкивания

3D-LUT стороной `render.snap_lut_side` = 32. Раскладка 2D: 32 слоя по 32×32, 16 слоёв в
строку → 512×64. Значение в ячейке `(r, g, b)` — ближайший цвет палитры к центру
соответствующего куба RGB.

Шейдер читает LUT с линейной интерполяцией **по слоям выключенной** — только `nearest`,
иначе интерполяция родит цвет вне палитры и обнулит смысл прохода.

### 3.7. Манифест

```
{
  "tile_w": 64,
  "pages": [{ "file": "city.png", "index_file": "city_index.png", "w": 2048, "h": 2048 }],
  "frames": {
    "<id>": { "page": 0, "x": 0, "y": 0, "w": 130, "h": 171,
              "anchor": [65, 171], "footprint": [2, 2], "kind": "building" }
  },
  "water": { "frames_x": 8, "frames_y": 8, "shallow": "<frame id>", "deep": "<frame id>" },
  "palette_sha256": "<sha256 файла corporator.hex>",
  "sha256": "<хеш манифеста без этого поля>"
}
```

`kind` из `{building, decor, unit, tile, road, water, glyph}` — по нему рендер выбирает
слой. `palette_sha256` попадает в пак ключом `render.palette_sha256`: если палитра
поедет, а атлас нет, правило поймает расхождение.

## §4. Земля, вода, утёс — этап V3

### 4.1. Чанковка

Сторона чанка `render.ground_chunk_tiles` = `placement.params.road_period_tiles` = 8.
Равенство не совпадение: шов чанка обязан ложиться на ось дороги, иначе он режет тайл
пополам и виден.

Для каждого чанка `(cx, cy)`:

1. Собрать тайлы `[cx*8 .. cx*8+7] × [cy*8 .. cy*8+7]`.
2. Отрисовать в `RenderTexture` размера AABB чанка плюс запас на утёс и на выступ
   спрайтов земли.
3. Порядок внутри чанка: сортировка по `(ty, tx)` — как `scene.py:224`.
4. Вода в чанк **не** печётся: она отдельным анимированным слоем.
5. Готовый чанк — один `Sprite`, позиция из `tileOrigin` угла чанка минус запас.

Итого ~64 спрайта земли вместо 3969 ромбов. Перепечь чанк требуется только когда
изменился вид тайла (постройка, снос) — тогда перепекается один чанк, не карта.

### 4.2. Утёс и берег

`scene.py` рисует утёс полосой `CLIFF_DEPTH = 11` px под каждым краевым тайлом суши.
Рендер повторяет это, но не полосой одного цвета, а тремя слоями по `TZ_ART.md` §3.4:
порода, тень породы, кромка. Число слоёв и их высоты — ключи `render.cliff_*`.

Берег (`shore`) — тайлы суши, соседствующие с водой. На них ложится вид `beach` из
`TZ_ART.md`, застройке они не подлежат (`L187`).

### 4.3. Тень острова

`scene.py` делает силуэт суши и утёса, смещает на `(7, 7)` и перекрашивает палитру
функцией `darken_under` — без альфа-бленда, чтобы не выйти из палитры. Рендер делает то
же: смещение `render.island_shadow_offset_px`, перекраска той же таблицей, полученной из
`art/pipeline/palette.py:darken_under`. Таблица кладётся в LUT как дополнительная строка
`lut_phases.png` — так шейдер обходится одним механизмом.

### 4.4. Вода

Пространственная фаза остаётся как в эталоне: `(tx mod 8, ty mod 8)`.
Временная фаза добавляется сдвигом столбца:

```
cityMinuteOfDay = cityTime / minute_len          // целочисленно, из clock.ts
step  = (cityMinuteOfDay * render.water_steps_per_city_minute) / 1
phase = (tx + step) mod frames_x
frame = atlas.water[(phase, ty mod frames_y)]
```

Глубина — как в эталоне: если в радиусе `render.shallow_reach_tiles` = 2 есть суша,
берётся мелкая вода, иначе глубокая.

Вода рисуется одним `ParticleContainer` или батчем спрайтов; при 1340 водных тайлах и
одном кадре смены на шаг это дешевле, чем перепекать текстуру.

Волна у берега — отдельная тонкая полоса кадров из атласа воды по контуру `shore`,
фаза той же формулой. Водопад — вертикальная лента кадров на тайлах утёса, помеченных
`waterfall` в сцене (`TZ_ART.md` §3.5).

### 4.5. Небо и облака

Фон — не один цвет, а вертикальный градиент **по ступеням палитры**: рампа берётся из
фазы, число ступеней `render.sky_bands`. Градиент ступенями, не плавный: плавный родит
цвета вне палитры (проход защёлкивания их вернёт, но полосы станут грязными — лучше
задать ступени сразу).

Облака — 3–4 спрайта из `TZ_ART.md`, движение по X со скоростью
`render.cloud_tiles_per_city_hour`, зацикливание по ширине сцены, параллакс
`render.cloud_parallax_bps` относительно камеры.

## §5. Спрайты, оверлеи, подписи — этап V4

### 5.1. Слой спрайтов

Источник объектов — `generated.placement.scene.objects` из пака (`D-V-2`), каждый
`{ id, tile: [tx, ty] }`. Плюс живые объекты из снапшота состояния: у них поверх базового
спрайта ложится оверлей уровня и бейдж.

Реализация: один `Container` с `sortableChildren = false` и вручную отсортированным
массивом (сортировка один раз при построении, пересортировка только при изменении набора).
Все спрайты — из одной страницы атласа, поэтому батч не рвётся.

### 5.2. Оверлеи уровня

`derived.level_overlays` уже задаёт словарь: уровень L рисует `L−1` пипов и `L−1` рядов
света, максимум добавляет антенну. `sprite_id` от уровня не зависит (`L180`).

Позиция пипов: над передним углом футпринта, шаг `render.level_pip_step_px`,
якорь `render.level_pip_offset_px`. Ряды света — включение соответствующих пикселей
свечения: не новый спрайт, а прибавка к каналу G в шейдере через маску оверлея.
Антенна — отдельный кадр атласа `overlay_antenna`.

### 5.3. Бейджи состояния

`docs/WORLD.md` §9: вид бейджа по префиксу кода. `IDLE_NO_ENERGY` и `IDLE_NO_COMPUTE` —
shortage (красный), `IDLE_NO_AGENT` — occupancy (серый). Каждый `IDLE_*` либо на сцене,
либо помечен `log_only` (`L181`).

Бейдж — кадр атласа плюс пульсация альфой периодом `render.badge_pulse_city_minutes`.
Пульсация от часов города, не от кадровой дельты (`D-V-8`).

**Это то место, которое `HUD.md` запрещает срезать:** «Нехватка ресурса видна на сцене.
Красный значок над зданием, а не только строка в логе. Иначе игрок ищет проблему
вслепую.» Тест `shortage_badge_on_scene` обязан падать, если бейджа нет.

### 5.4. Подсветка футпринта и выбор

Наведение: контур ромба футпринта, толщина `render.hover_outline_px`, цвет — рампа
`highlight`, альфа `render.hover_outline_alpha_bps`. Уже доказано в
`art/pipeline/scene.py --grid`.

Выбор: тот же контур плюс приподнятый спрайт на `render.select_lift_px` и подпись.
Клик по тайлу без здания — выбор участка (для `commit:build`), клик по зданию — карточка
(`building_card`).

### 5.5. Подписи зданий

Как в мокапе: плашка с именем, тикером района и уровнем над зданием.

- Шрифт — битмап-атлас глифов (`TZ_ART.md` §5), не CSS: подпись живёт в мировых
  координатах и масштабируется вместе с камерой.
- Порог видимости: `zoom >= render.label_min_zoom_num / render.label_min_zoom_den`.
  Ниже порога подписи не рисуются вообще (`L345`) — иначе на 1/8 масштабе кадр
  превращается в кашу.
- Коллизии: подписи сортируются по приоритету (`beacon` > `base` > `synergy` > остальное),
  затем по `depth`. Подпись, чей AABB пересекает уже размещённую, **пропускается**.
  Уменьшать кегль запрещено: пиксельный шрифт на дробном кегле разваливается.
- Текст — из `content/strings/ru.json` по ключу, не литералом (`L343`).

## §6. Сутки и свет — этап V5

### 6.1. Откуда берётся фаза

Часы города — `apps/client/src/clock.ts`, единственное место с `Date.now` (`L275`).
Границы фаз — `generated.placement.phases`, выведенные из `time.json`
(`dawn_hour = efficiency_recalc_hour`, `day_hour = bank_open_hour`,
`dusk_hour = bank_close_hour`, `night_hour = сумерки + (день − рассвет)`), `L179`.

Ни одного часа литералом в рантайме (`L335`).

```
hour        = cityHourOfDay(cityTime)
phaseIndex  = индекс фазы, в чей интервал попал hour
nextIndex   = (phaseIndex + 1) mod phaseCount
minutesLeft = минут города до конца фазы
blendWindow = render.phase_blend_city_minutes
blendBps    = minutesLeft >= blendWindow ? 0
                                         : 10000 - minutesLeft * 10000 / blendWindow
```

`blendBps` — доля следующей фазы, целое в bps, монотонно растёт к границе и обнуляется
сразу после. Тест `phase_blend_is_monotonic` проверяет монотонность и отсутствие разрыва.

### 6.2. Шейдер фазы

Один фрагментный шейдер на слои 1–5 (вода, тени, земля, спрайты). Входы:

```
uniform sampler2D uIndex;      // индексный атлас
uniform sampler2D uLut;        // lut_phases.png
uniform float uPhaseA;         // строка текущей фазы
uniform float uPhaseB;         // строка следующей фазы
uniform float uBlend;          // blendBps / 10000
uniform float uEmissive;       // усиление свечения текущей фазы
```

Логика:

```
idx  = floor(texture(uIndex, vUv).r * 255.0 + 0.5)
a    = texelFetch(uLut, ivec2(idx, uPhaseA), 0).rgb
b    = texelFetch(uLut, ivec2(idx, uPhaseB), 0).rgb
base = mix(a, b, uBlend)
glow = texture(uIndex, vUv).g * uEmissive
color = base + glow * lampColor
alpha = texture(uIndex, vUv).a
```

Смешивание `mix` и прибавка `glow` выводят цвет из палитры — это ожидаемо и допустимо
**внутри** прохода, потому что финальный проход §6.4 возвращает кадр в палитру.

`texelFetch` требует WebGL2 / GLSL ES 3.00. Если целевой контекст даёт только WebGL1,
используется `texture2D` с `nearest` и вычислением UV из `(idx + 0.5) / 64`. Оба варианта
обязаны дать одинаковый кадр — тест на равенство между ветками.

### 6.3. Свет в окнах и фонари

`uEmissive` — из фазы: `0` в `day`, иначе `render.emissive_gain_bps / 10000`, умноженное
на профиль фазы. Фонари включены в `derived.lanterns_on_phases` = `[dawn, dusk, night]`
(`L336`, `L189`).

Гало фонаря и окна — не блюр, а предпечённый кадр атласа `glow_small` / `glow_large`
радиусом `render.lamp_glow_radius_px`, нарисованный ступенями палитры и наложенный
**без** аддитивного режима: аддитив с последующим защёлкиванием даёт грязь на границах.
Ступени гало — из рампы `amber`, число ступеней `render.glow_bands`.

Фары машин — тот же `glow_small` с меньшей альфой, включаются в те же фазы.

### 6.4. Финальный проход защёлкивания

Кадр из слоёв 0–9 лежит в `RenderTexture`. Проход выводит её на канвас через шейдер:

```
uniform sampler2D uFrame;
uniform sampler2D uSnap;      // lut_snap.png, 512x64
uniform float uSide;          // render.snap_lut_side

c   = texture(uFrame, vUv).rgb
// координата в 3D-LUT, слои по 16 в строку, nearest по всем осям
out = lookupSnap(uSnap, c, uSide)
```

После этого прохода в кадре физически не может быть цвета вне палитры. Тест
`frame_uses_only_palette` читает пиксели канваса и проверяет принадлежность множеству из
53 значений — 100%, без допуска.

Проход выключается только флагом отладки, и этот флаг не существует в продакшн-сборке.

## §7. Камера и ввод — этап V6

### 7.1. Модель камеры

Состояние: `{ centerTileX, centerTileY, zoomIndex }`. Позиция — в тайлах, не в пикселях:
при смене зума центр обзора сохраняется.

Уровни зума — только `derived.zoom_levels`: целые пиксельные масштабы, степени двойки, от
`derived.zoom_min_scale_num/den` = 1/8 до `zoom_max_scale` = 2 (`L185`, `L337`).
Промежуточных масштабов нет: дробный масштаб на пиксельной графике даёт мерцание.

Смена зума анимируется по времени `render.zoom_step_ms`, но **промежуточные кадры
рисуются масштабом целевого уровня** — анимируется положение, не масштаб.

Клампы: центр ограничен `derived.camera_bounds` (`min_x/y = -2`, `max_x/y = 64`) плюс
`camera_edge_margin_tiles`. На минимальном зуме остров целиком в безопасном
прямоугольнике — это уже проверено `L185`.

### 7.2. Ввод

| жест | действие | ключ пака |
|---|---|---|
| перетаскивание левой кнопкой | панорама | `render.pan_deadzone_px` |
| колесо | зум к курсору | `render.zoom_step_ms` |
| пинч двумя пальцами | зум к центру пинча | `render.pinch_step_bps` |
| одиночный тап/клик | выбор тайла или здания | `render.tap_max_move_px` |
| двойной клик | зум на шаг к точке | `render.double_tap_ms` |
| стрелки, WASD | панорама шагом | `render.pan_tiles_per_city_second` |
| `+` / `−` | зум на шаг | — |
| `Esc` | снять выбор | — |

Порог `tap_max_move_px` отделяет тап от панорамы: без него на тач-устройстве каждый
скролл выбирает тайл.

Инерция панорамы — `render.pan_inertia_ms`, гасится линейно. Инерция обязана
заканчиваться на целом пикселе мирового пространства (`roundPixels`).

### 7.3. Клик и HUD

Панели HUD лежат поверх канваса и обязаны съедать событие: канвас получает
`pointerdown` только если цель события — сам канвас. Атака `A-V-11` проверяет, что клик
по панели не проходит на сцену.

Клик по тайлу отдаёт наверх `{ tileX, tileY, objectId | null }`. Это закрывает текущий
дефект: `LiveRoot.tsx:64` отправляет `commit:build` с захардкоженным `tile:{q:0n,r:0n}`.

Клик по зоне в `DISTRICT OVERVIEW` (`HUD.md` §5.4) ведёт камеру в
`derived.zone_centroids` (`docs/WORLD.md` §8).

## §8. Движение и FX — этап V7

Правило одно и оно жёсткое: **любая фаза анимации — чистая функция от `city_time` и
сида юнита.** Кадровая дельта используется только для интерполяции между двумя
вычисленными состояниями, никогда как источник фазы. Иначе голдены не воспроизводимы
(`D-V-8`, `L338`).

Сид юнита — тот же механизм, что в `content/world.py:world_prng`: восемь байт
`sha256(f"{city_id}:layout:{stream}:{index}")`. В TypeScript берётся из
`packages/contentpack` (там уже есть локальный sha256), не из `Math`.

### 8.1. Машины

`generated.placement.vehicles` даёт 50 позиций на дорожных тайлах.

Маршрут: от стартового тайла машина идёт по дороге, на каждом перекрёстке выбирая
направление детерминированно — `world_prng(city_id, "vehicle", index * K + step) mod
доступных направлений`, где `step` растёт с пройденными тайлами. Разворот назад
исключается, если есть другой вариант.

Скорость: `render.vehicle_tiles_per_city_minute`. Положение внутри тайла —
`frac = (cityTicks * speed) mod 1`, интерполяция между центрами соседних тайлов.

Порядок отрисовки — тот же `depth`, что у зданий: машина обязана заезжать за здание, а
не поверх него.

Машина не занимает лот и не ссылается на ключ модификатора (`L190`).

### 8.2. Дроны

`generated.placement.drones` даёт 6 позиций с `block_id`. Дрон летает над своим
кварталом по замкнутой траектории: прямоугольник периметра квартала, скорость
`render.drone_tiles_per_city_minute`, высота `render.drone_altitude_px` плюс покачивание
амплитудой `render.drone_bob_px` периодом `render.drone_bob_city_minutes`.

Тень дрона — ромб на земле под ним, альфа тем меньше, чем выше.

### 8.3. Прочая жизнь

| элемент | движение | ключ |
|---|---|---|
| лопасти ветряка | кадры вращения из атласа | `render.turbine_frames`, `render.turbine_period_city_minutes` |
| дым труб | вертикальная лента кадров | `render.smoke_frames` |
| флаг на City Hall | кадры колебания | `render.flag_frames` |
| огонёк на биллборде | смена кадра вывески | `render.billboard_period_city_minutes` |
| птицы | пролёт раз в N часов города | `render.birds_per_city_day` |
| волна у берега, водопад | §4.4 | — |

Все они — кадры атласа, не процедурная генерация: процедурное рождает цвета вне палитры.

### 8.4. FX реакции на тик

При событии тика:

- **Попап значения** над зданием: `+62 Capital`, длительность `render.fx_popup_ms`,
  подъём `render.fx_popup_rise_px`, затухание ступенями альфы.
  **Число берётся из снапшота сервера.** Клиент его не считает (`L357`,
  `docs/SCREENS.md` §1 закон E).
- **Вспышка окон** при валидном тике: кратковременное усиление `uEmissive` в пределах
  `render.fx_tick_glow_bps`.
- **Прогресс стройки**: кадры строительных лесов из атласа по доле готовности из
  снапшота, не по локальному таймеру.
- **Красный бейдж** при `IDLE_*` — §5.3.

Строка настроек «анимация тика» (`settings_rows`, `client_only`, `v1=live`) выключает
слой FX целиком, не ломая остальное.

## §9. Границы пакета и код

### 9.1. `packages/render`

Заводится с `arch.packages` (`D-V-9`):

```
render.allowed_deps = ["protocol", "contentpack"]
```

Не видит `engine`, `chainport`, БД, сервисы. Клиент импортирует рендер. Слой в
`derived.layer_order` — между `contentpack` и `apps/client`. Регистрация в
`.dependency-cruiser.cjs` обязательна: `L226`–`L230` иначе не пройдут.

Структура:

```
packages/render/src/
  index.ts          публичный фасад: createScene, destroyScene, applySnapshot
  geometry.ts       §2, чистые функции, без Pixi
  atlas.ts          загрузка манифеста, кадры, валидация хеша палитры
  ground.ts         §4.1–4.2, чанковка и утёс
  water.ts          §4.4
  sky.ts            §4.5
  sprites.ts        §5.1
  overlays.ts       §5.2–5.4
  labels.ts         §5.5
  light.ts          §6, шейдеры фазы и защёлкивания
  camera.ts         §7.1
  input.ts          §7.2
  motion.ts         §8.1–8.3, чистые функции положения
  fx.ts             §8.4
  budget.ts         замер вызовов рисования и памяти текстур для §7 плана
  shaders/*.glsl    исходники шейдеров, читаются как строки на сборке
```

Файл длиннее ~400 строк делится. `geometry.ts` и `motion.ts` не импортируют Pixi вообще —
они чистые и тестируются без канваса.

### 9.2. Дисциплина

- TypeScript strict, включая `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
- `any` запрещён, `!` запрещён, поля `readonly` по умолчанию.
- Ветвление по вариантам — исчерпывающий `switch` с never-guard.
- Числовые литералы в `packages/render/src` — только `0`, `1` и индексы. eslint-селектор
  `no-restricted-syntax` на `Literal[value>=2]` расширяется на этот путь тем же правилом,
  что охраняет `packages/engine/src`. Исключение — файлы шейдерных строк, где числа
  приходят как uniform, а не как литерал (`L340`).
- `Date`, `performance`, `Math.random` — запрещены. Время только из `clock.ts`,
  случайность только из `world_prng`.
- Рендер не пишет состояние и не зовёт тик (`L339`). Импорт `engine` остаётся
  `preview_only` у клиента и в рендер не попадает.

### 9.3. Отсутствие GPU

Инициализация: попытка WebGL2, затем WebGL1. Обе неудачи → рендер не создаётся, клиент
показывает предпечённый кадр (`art/out/atlas/fallback.png`, тот же остров в фазе `day`) и
код `RENDER_NO_GPU` из `codes.json`. HUD работает полностью: игра остаётся играбельной
без сцены (`D-V-16`, `L352`).

Код `RENDER_NO_GPU` добавляется в `codes.json` и в `content/strings/ru.json` в том же
заходе, что и ветка — иначе `L146`/`L247` поймают.

### 9.4. Профили качества

Три профиля: `high`, `medium`, `low`. Выбор один раз на загрузке по детерминированной
пробе возможностей (WebGL2, максимальный размер текстуры, число текстурных юнитов), не по
измеренному fps: измеренный fps сделал бы кадр невоспроизводимым.

| что режет | high | medium | low |
|---|---|---|---|
| облака и параллакс | да | да | нет |
| гало фонарей | да | да | нет |
| волна у берега, водопад | да | нет | нет |
| птицы, дым, флаг | да | нет | нет |
| анимация воды | да | да | шаг реже |
| проход защёлкивания | да | да | **да** |

Проход защёлкивания не режется ни в одном профиле: это инвариант, а не украшение.
Голдены снимаются на `high`.

## §10. Тесты рендера

### 10.1. Чистые, без канваса

- `geometry.ts`: `tileOrigin`, `tileCenter`, `frontVertex`, обратное преобразование на
  четырёх углах и центре ромба, на всех уровнях зума.
- `motion.ts`: два вызова с одним `city_time` дают одинаковое положение; машина всегда на
  дорожном тайле; дрон всегда над своим кварталом.
- `light.ts`: `blendBps` монотонен, обнуляется после границы, не выходит из `[0, 10000]`.
- `atlas.ts`: манифест с чужим `palette_sha256` отвергается.

### 10.2. С канвасом, в браузере

Инструмент — headless-браузер с фиксированным масштабом устройства, программным
растеризатором и **замороженными часами города** через тестовый хук `clock.ts`.
Зависимость новая, обоснование в отчёте этапа и запись в `arch.toolchain` обязательны.

Уровни проверки — `D-V-15`:

1. **Палитра.** Все пиксели кадра ∈ 53 цвета. Без допуска. Гоняется в четырёх фазах.
2. **Точки-пробы.** Пиксель в переднем углу футпринта City Hall; центр известного тайла
   воды; окно известного здания в фазе `night`; тайл дороги под машиной в момент
   `city_time = T`. Точное равенство цвету палитры.
3. **Голден.** Полный кадр против эталона: не более `render.golden_pixel_delta_bps`
   отличающихся пикселей при канальной разнице не более `render.golden_channel_delta`.

Голдены хранятся в `art/out/golden/` и пересоздаются только осознанной командой, никогда
автоматически. Пересоздание фиксируется в отчёте этапа с причиной.

### 10.3. Бюджеты

`budget.ts` снимает: число вызовов рисования за кадр, число спрайтов, байты текстур,
среднее время кадра за окно измерения. Значения сравниваются с потолками пака. Метрика
снимается с наблюдения, не с порога (`L326`, `L351`): подстановка
`observedFromThresholds` в рантайм замера — ловится правилом.
