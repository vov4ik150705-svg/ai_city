## Порядок работы

Этапы C0–C11 из docs/reports/PLAN_CODE.md §4 выполняются строго по номерам.
Этап C(N+1) не начинается, пока гейт C(N) не зелёный и отчёт C(N)_final.md не написан.

Порядок нарушать нельзя: C0 задаёт форму фазы (воркспейс, запреты линтера, золотые
векторы, односторонний кодоген), C1 задаёт байты. Начнёшь C3 раньше C1 — получишь
сервис, который сериализует по-своему, и перепишешь его целиком.

У каждого этапа в плане десять полей: цель, строка ROADMAP, входы, выходы, команда
гейта, инвариантные тесты, критерий готовности, объём, зависит от, риски. Ни одно поле
не игнорируется. Критерий готовности выполняется буквально, а не «по смыслу».

## Сквозные законы — не ломаются ничем

Пак — единственный источник чисел и форм. В рантайме нет числовых литералов, кроме
0, 1 и индексов. Одно и то же число в двух местах — дефект. Выводимое значение
считается, а не хранится. Версии инструментов, пороги метрик, периоды, лимиты, TTL —
ключи пака, не строки в конфигах.

Тик — чистая детерминированная функция (pack, state, inputs). Внутри тика запрещены
LLM, Math, Date, performance, process, несидированная случайность, любой I/O.
Случайность только hash(city_id, tick_index, agent_id). Время только city_time,
никогда время клиента и никогда системные часы внутри тика.

В хеш-путь идёт только bigint. number и float в сериализации запрещены типами.
Загрузчик пака свой, bigint-safe: целое в bigint, нецелое число — ошибка загрузки,
дубликат ключа — ошибка, несовпадение pack_hash — отказ закрыто. Это единственный
закрытый контур; все остальные сервисы fail_mode = open и права блокировать тик
не имеют.

Инварианты BRIEF §3 и десять инвариантов D13 держатся всегда: касса, бюджет трения,
пропорциональное урезание фонда, I5, I7, I11, детерминизм тика, догон ≡ реплей,
байтовая стабильность layout v1, барьер демо. Запрещённый список BRIEF §3 и
corporator-canon §11 — запрещён и в коде тоже.

Python остаётся оракулом и гейтом, TypeScript — единственным рантаймом. Паритет
доказывается байтами золотых векторов, а не чтением двух реализаций рядом.

Сгенерированный файл руками не правится: правится генератор и параметры. Кодоген
односторонний, `--check` в гейте роняет любую ручную правку.

Новая функциональность выражается строкой в данных: параметр, модификатор, код
отказа, строка таблицы. Фича, требующая нового кода вне уже описанных пакетов,
в v1 не входит. Изменил механику — правь DESIGN.md в том же заходе, одним-двумя
предложениями, а не разделом целиком. Молча переписывать канон нельзя; принципиальное
расхождение — спроси до кода, а не после.

## Дисциплина кода

TypeScript strict, включая noUncheckedIndexedAccess и exactOptionalPropertyTypes.
`any` запрещён; на границе с внешним JSON — unknown плюс немедленная валидация.
Оператор `!` запрещён. Поля readonly по умолчанию. Ветвление по вариантам —
исчерпывающий switch с never-guard, иначе новый вариант тихо провалится.

Чистое ядро, эффекты на краю. Никакой скрытой мутации входов. Никаких синглтонов
с состоянием в engine. Никаких абстракций «на будущее»: слой появляется, когда его
требует вторая реализация из пака, а не когда так красивее.

Идентификаторы английские. camelCase в TypeScript, snake_case в данных, JSON и SQL.
Ключи пака не переименовываются — они контракт. Файл длиннее ~400 строк делится.
Barrel-реэкспорты через границу слоя запрещены. Импорт только вниз по таблице слоёв,
проверяется dependency-cruiser, конфиг которого сгенерирован из пака.

Зависимости: у engine пустой dependencies, и это проверяется. В остальных пакетах
новая зависимость допускается только с обоснованием в отчёте этапа и записью
в arch.toolchain. Библиотека десятичной арифметики в хеш-путь не берётся никогда.

Ошибки: доменный отказ игрока — HTTP 409 и код из codes.json; транспорт — закрытый
набор кодов и их HTTP из секции «T12: http». Поле message запрещено, прозы на проводе
нет, текст рендерит клиент из content/strings/ru.json.

Комментарии только про ограничение или инвариант, который код не выражает, со ссылкой
на раздел канона вида `docs/TICK.md §8`. Комментарий-пересказ строки, комментарий
«почему мой код правильный» и TODO без владельца и id запрещены. Мёртвого кода нет:
закомментированные блоки и неиспользуемые экспорты удаляются. Заглушка допустима
ровно одна — та, что объявлена в паке (v1 = stub, ответ FEATURE_NOT_IN_V1, spend = none).

Стиль форматирования не обсуждается: eslint и prettier автоматом.

## Тесты — таксономия, обязательная на каждом этапе

Векторный паритет: байты берутся из Python-оракула (content/out/vectors/*), сравнение
по Uint8Array, а не по значению и не по повторной сериализации своего же объекта.

Property-тесты (fast-check): детерминизм тика, догон ≡ реплей, пропорциональность
урезания фонда, отсутствие float в байтах, независимость байтов от порядка ключей
входа. Число прогонов — ключ пака, не литерал в конфиге.

Конструкционные пробы: имя теста дословно равно имени пробы из колонки tests таблицы
«T12: roadmap» и из docs/reports/T12_final.md §4. Одна проба — один тест с тем же
именем, чтобы гейт этапа читался как строка дорожной карты.

Негативные: каждый код отказа хотя бы раз получен от системы; каждый закрытый контур
хотя бы раз уронен; каждый негативный вход загрузчика пака даёт ошибку с кодом.

Интеграционные: реплей из сохранённых байтов, хвост от снапшота против полного
реплея, идемпотентность intent_id, устаревшая expected_city_time, производный лимит
команд, барьер демо на уровне БД.

Контрактные: биекция эндпоинтов и commit:*, каналы как разбиение state_sources,
карта транспортных кодов в HTTP, состав снимка состояния.

Перф: бюджеты только из docs/reports/GATE_PERF.md, новых чисел не заводить.

Покрытие измеряется не процентом, а падением: тест, для которого не показан красный
прогон на подготовленном входе, тестом не считается.

## Гейт этапа

Запускается целиком, результат читается числами из вывода, а не из памяти:

    python content/build.py
    python content/lint.py
    python content/vectors.py
    python content/codegen.py --check
    pnpm -w install --frozen-lockfile
    pnpm -w run gate      (tsc --noEmit, eslint, depcruise, vitest run)
    pnpm -w run vectors
    python content/attack.py --only <затронутые правила>   на каждом шаге
    python content/attack.py --jobs 8                      перед публикацией пака

Плюс ReadLints на все правленные файлы. Файл, который не разобрался, готовым
не обсуждается. Изменил пак — поднял pack_version и записал причину по CONTENT.md §5;
хеш пака в отчёте — из поля hash, а не из прошлого сообщения.

Слова «должно работать», «скорее всего проходит», «логика верна» результатом
не считаются. Не запустил — не сделал.

## Адверсариальное ревю — обязательный третий проход

После зелёного гейта ты атакуешь собственную работу. Для каждого нового правила,
формулы, инварианта и теста строится вход, на котором он должен упасть, и показывается,
что он падает. Правило, которое никогда не срабатывает, — декорация.

Чеклист атак:

    какой вход обходит правило, формально его не нарушая
    границы: ноль, единица, потолок, пустой список, максимум, отрицательное
    последовательность действий игрока, дающая недопустимый результат
    ложь и молчание внешнего источника: оракул, RPC, IPFS, LLM, БД, часы
    какое число можно поменять так, чтобы гейт промолчал, а экономика поехала
    конкурентность: два запроса на один nonce, ваучер, intent_id, слот
    перезапуск процесса посередине: частичная запись, дубль в outbox, повтор выплаты
    подмена pack_hash, подмена байта пака, старый пак на новой записи
    клиент, притворяющийся сервером: запись состояния из предпросмотра, своё время
    потеря точности: 2^53, деление, остаток, округление не туда

Найденные дыры закрываются здесь же: новые векторы атак дописываются в
content/attack.py и в TS-набор с тем же именем, новые правила — в content/lint.py.
Выжившая атака, о которой не сказано, означает, что ревью не пройдено.

## Артефакты этапа — на диск, не в чат

    docs/reports/C<N>_recon.md   что прочитано, что найдено в дереве, риски этапа
    docs/reports/C<N>_code.md    что написано, ключевые решения, отклонения от плана
    docs/reports/C<N>_rules.md   новые правила и пробы: id → что ловит → вход падения
    docs/reports/C<N>_final.md   таблица гейта с числами, список атак, расхождения,
                                 готовность и следующий шаг

Вся аналитика, промежуточная математика, длинные списки и полные тексты пишутся
в файлы молча. В чат они не выводятся ни при каких условиях.

## Формат ответа в чат — до 20 строк, фиксированный

    === STEP PASSPORT ===
    Этап: C<N> — <цель одной фразой>
    Файлы: <созданные и изменённые пути>
    Гейт: build <итог> | lint <правил>/<ошибок> | pack <hash кратко>/<pack_version>
          vectors <sha кратко> | tsc/eslint/depcruise <итог> | vitest <passed>/<failed>
          attack <проб>/<нашлось>
    Атаки: <сколько проведено>, выстояло <сколько>, нашлось <что именно, id>

Запрещено выводить в чат: полные тексты файлов, таблицы, длинные списки, пересказ
прочитанного, размышления «почему сделано именно так», извинения и планы вместо
результата. Больше двадцати строк или проза вместо паспорта — задача не принята.

## Развилки и границы

По каждой развилке — одна рекомендация с причиной, а не список опций на выбор.
Принципиальное расхождение с каноном — вопрос до кода.

Коммиты только по просьбе. Папка репозитория ai_city не переименовывается.
art/raw не трогается. Второй список этапов, зависимостей, инвариантов или кодов
не заводится: источник один — пак.

Вне кодовой фазы v1 и не начинается: Solidity, живой RPC до C10, призы сезонов
до C11, live-корень merkle, S_min по RPC, снимок цены LLM, LLM внутри тика.

## Определение готовности

Этап закрыт, когда его команда гейта зелёная в выводе, каждый новый тест показал
красный прогон на подготовленном входе, каждая проведённая атака названа, и отчёт
с числами лежит в docs/reports/. Всё остальное — незакрытый этап.
