## 2. Принятые решения (не обсуждать)

Архитектор. Исполнять, не предлагать развилку вместо них.

**Р1. Источник и рантайм разделены.** Жирный `.blend` — авторский источник, в git не кладётся. Конвейер экспорта даёт тонкие артефакты: масса острова отдельным файлом, каждое здание отдельным файлом. Смотрелка `view.html` показывает **тонкие** файлы, а не запечённую сцену на 236 МБ.

**Р2. Основной материал сцены — вершинные цвета, не текстуры.** Рельеф, мощение, грунт, декор, небо, облака — один (или считанные) материал с атрибутом цвета вершин. Текстура остаётся только там, где без неё нельзя: бренд и вывеска на фасаде здания. Это режет вес, число материалов и вызовы отрисовки.

**Р3. Повторяющийся декор — инстансы.** В Blender — связанные дубликаты (`Alt+D`, общие данные меша), дети одного Empty на семейство. На экспорте — `EXT_mesh_gpu_instancing`. Сорок деревьев = один вызов отрисовки, не сорок.

**Р4. Свечение — не карта эмиссии на каждом здании.** Ночной кадр = (1) маленькие эмиссивные меши полос-вывесок, (2) эмиссивные фонари, (3) bloom в клиенте на I7. Не «сделать всем зданиям emission map».

**Р5. Точек привязки не меньше 23, ставить 26.** `generated.balance.build_slots`: 11 на уровне 1, 23 на уровне 7 (`content/out/GENERATED.md`, таблица «T2: уровень города»; формула `BALANCE.md` §9). Свободных мест должно хватать на 23 постройки. Ставить **26** Empty `anchor_*`. Это ответ на открытый вопрос `PLAN_ISLAND.md` §4. Занятость точки — состояние экономики **этого** игрока, не свойство карты.

## 4. Бюджет кадра

Часть критерия «готово», не пожелание. До I7 числа живут **здесь**. На I7 они переезжают в `content/params/render.json` (секция `render`) и в `docs/reports/GATE_VISUAL.md`. В `packages/render/src` числовых литералов кроме 0, 1 и индексов быть не должно (`L340`).

| что | потолок | почему |
|---|---:|---|
| первая загрузка целиком | 12 МБ | сейчас ≈ 236 + 227 = 463 МБ (live glb + 18 моделей) |
| масса острова с мощением | 1.5 МБ | канон 146.8 КБ / 4130 лиц; запас на два яруса, шашку, декор-инстансы, облака |
| одно здание | 350 КБ | сейчас 10.1…17.0 МБ |
| библиотека декора целиком | 600 КБ | десятки объектов из единиц мешей, GPU-инстансы |
| треугольников в кадре | 250 000 | low-poly диорама, не скан Meshy |
| вызовов отрисовки | 100 | инстансы + мало материалов |
| уникальных материалов | 16 | вершинный цвет на земле/декоре; текстура только на вывесках |
| сторона текстуры | 1024 | KTX2 или WebP, не PNG |
| частота кадров | 60 при 1080p на встроенной графике | `render.params.fps_target` уже 60; проверить на тонких файлах, не на 236 МБ |

Арифметика потолка первой загрузки: 1.5 + 18 × 0.35 + 0.6 = 8.4 МБ, запас до 12 МБ — не приглашение расползтись.

Нынешние `draw_calls_max = 4096` и прочие потолки v3 в `render.json` — **архив клеточного кадра**. На I7 их сменить на таблицу выше (или на измеренное ниже потолка, не копировать потолок в `observe.*` — `L351`).

Клиент (I7) грузит `island_mass.glb` + нужные `runtime/buildings/*.glb`. Смотрелка показывает те же тонкие байты (мультизагрузка Three.js **или** `island_view.glb`, собранный из них). Не показывать 236 МБ.

Инструмент сжатия, которого в репозитории нет и который I0 ставит:

```
pnpm add -D -w @gltf-transform/cli
```

Пакет `@gltf-transform/cli`, бинарь `gltf-transform`. Что делает: inspect, дедуп, prune, weld, resize текстур, WebP, meshopt (`EXT_meshopt_compression`). Не процедурный генератор карты.

Почему meshopt, а не Draco: в Three.js 0.185.1 (`packages/render/package.json`) уже есть `three/addons/libs/meshopt_decoder.module.js`. Draco потребовал бы отдельный wasm-лоадер. KTX2 разрешён таблицей, но `GLTFLoader` без `setKTX2Loader` + Basis transcoder падает на KTX2. **I0 по умолчанию: WebP 1024 + meshopt.** KTX2 — только если тот же чат I0 либо явно I7 подключает `KTX2Loader`. Не блокировать диету установкой `toktx`.

Контракт I0 → I7: если в GLB есть `EXT_meshopt_compression`, I7 обязан вызвать `loader.setMeshoptDecoder(MeshoptDecoder)` до `load`.

Ключ: `island_form`.

**Цель.** Владелец смотрит на то, что поедет в браузер: тонкая масса, тонкие здания, смотрелка не грузит 236 МБ.

**До неё.** Ничего. Это предусловие I1–I8.

**Гайд.**

1. Замерить исходное (не верить паспорту):
   ```
   python -c "from pathlib import Path; p=Path('art/island_v3/island.glb'); print(p.stat().st_size)"
   ```

### I1. Рельеф и два яруса

Ключ: `island_terrain`.

**Цель.** С орбиты читается перепад: утопленная центральная площадь, кольцо выше, низ — скала, не тонкая плита.

**До неё.** I0: смотрелка и экспорт идут в `runtime/`.

**Гайд.** Blender 4.5, `island.blend`. Работать объектом `Island`. Числа: площадка 7200×7200 м (`ISLAND_SCALE = 10`). Сторона площади ≈ 40% от 7200 = 2880 м, ставить **2800 м**. Перепад ярусов **180 м**. City Hall с 1120 до ≈ 1800 м — высота модели, не рельеф; константа `HALL_HEIGHT` в `build_island.py` сейчас `280.0 * BUILDING_SCALE` = 1120. На I1 Hall не рескейлить (это I5); после опускания площади — только посадить его на новый пол.

Рекомендуемая схема ярусов: **опустить только площадь на 180 м, кольцо оставить на z ≈ 0.** Тот же перепад, кольцо и утёс не перестраиваются, канон массы меньше рискует стать новым блином. Не поднимать кольцо на +180 (пришлось бы двигать 18 зданий и стык с утёсом). Не сжимать площадку к 3600. `ISLAND_SCALE` не растить.

Полярная треугольная сетка не даёт прямоугольную яму «выделить и Extrude»: граница пойдёт по треугольникам. Способ — Knife Project из ортогонального вида сверху (мануал 4.5: `Mesh ‣ Knife Project`).

1. `File ‣ Open` → `art/island_v3/island.blend`. Object Mode (`Tab` переключает).
2. Сохранить копию: `File ‣ Save As` → `art/island_v3/island_pre_terrace.blend` (локально, не канон snapshot).
3. Резак: `Add ‣ Mesh ‣ Plane`, имя `PlazaCutter`. В Object Properties выставить Dimensions X=2800, Y=2800 (не Scale «на глаз»: после размеров `Ctrl+A` ‣ `Apply ‣ Scale`). Поставить над островом, XY = центр площадки (0,0), Z ≈ 200. Плоскость должна быть non-manifold (плоская) — иначе Knife Project 4.5 отвергнет резак.
4. Вид: `Numpad 7` (Top), `Numpad 5` пока в заголовке не будет Orthographic (не Perspective). Камера вида смотрит вдоль −Z. Без ортографии проекция ножа скосится.
5. Порядок 4.5 (не старый «сначала резак»): выделить `Island` ‣ `Tab` (Edit Mode). В Outliner `Ctrl+LMB` по `PlazaCutter`. Если Blender вылетает в Object Mode — включить `Edit ‣ Lock Object Modes`. `Mesh ‣ Knife Project`. В операторной панели (левый нижний) **не** включать Cut Through: нужен только топ, не дно утёса.

8. Резак `PlazaCutter` удалить (`X` ‣ Delete) — в GLB его быть не должно.
9. Object Mode. У каких из 18 зданий origin внутри квадрата 2800×2800 (как минимум `CityHall`): выделить, `G`, `Z`, `-180`, чтобы низ снова сел на площадь. Кольцевые здания не трогать.
10. Экспорт только через `export_runtime.py` (I0). `build_island.py` не запускать: он не режет рельеф, но пересобирает здания и при широком delete-цикле снесёт всё, кроме `Island`.
11. Смотрелка: тонкий `runtime/island_mass.glb`. С орбиты виден уступ. Низ утёса на месте (AABB z не обрезан к нулю; канон z −2517 не обязан совпасть поббайтно после правки топа, но обрыв должен остаться обрывом).

Альтернатива, которой **не** пользоваться первой: Boolean Difference кубом 2800×2800×высота. На полярной сетке 4130 лиц Exact-булеан часто даёт дыры и ломает утёс. Knife Project предсказуемее.

**Критерий.** Перепад топа читается с орбиты ≈ 180 м (линейка Blender: Edit Mode, ребро стенки, Item ‣ Dimensions Z ≈ 180). Площадь прямоугольная, не «звезда» по треугольникам. Площадка по-прежнему порядка 7200, не 3600. Канон `snapshots/canon_2026-09-06_island/` не перезаписан. Тонкая масса всё ещё ≤ 1.5 МБ.

**Чем проверять.** Blender Sidebar ‣ Item; `view.html` на `runtime/`; размер `island_mass.glb`; не открывать жирный bake.

### I2. Покрытие

Ключ: `island_ground`.

**Цель.** Двор — шашка серой плитки; к зданиям на кольце ведут дорожки; вне камня — грунт. Не тайлы `p`/`r`/`s` пака.

**До неё.** I0 и I1 (есть уступ площади).

**Бюджет кадра.** Суммарный остаток после зданий — около 100 000 треугольников на мощение, декор, облака и всё остальное вместе; декор обязан идти инстансами.

**Гайд.** Р2: вершинные цвета, не текстура и не второй материал земли.

Цвета брать из рампы `concrete` файла `art/palette/corporator.hex` (не выдумывать палитру): светлая плитка `#a3aec2`, тёмная `#707b92`, грунт `#2e3a16` (olive bridge той же палитры, не «случайный зелёный»). Шов шашки даёт чередование квадов, отдельный материал шва не заводить.

**Материал (один на остров, шаг один раз).**

1. Выделить `Island`. Properties ‣ Material. New, имя `IslandVertex`.
2. Shader Editor. Удалить лишние Image Texture, если они остались с импорта.
3. `Add ‣ Input ‣ Color Attribute`. Имя атрибута должно совпасть с Color Attribute меша (шаг ниже: `Color`). Color → Principled BSDF Base Color. Metallic 0, Roughness ≈ 0.85. Это режим экспорта `MATERIAL`: без связи Base Color атрибут `COLOR_0` в GLB не уедет.
4. Viewport Shading: Solid, цвет `Attribute` (мануал 4.5: иначе в Solid вершинный цвет не виден). В Material Preview / lookdev проверять тот же материал.

**Атрибут цвета.**

5. Properties ‣ Data (зелёная сетка) ‣ Color Attributes ‣ `+`. Name `Color`, Domain **Face Corner**, Data Type **Byte Color**. Face Corner даёт острый край плитки; Vertex размоет шашку по рёбрам.

**Площадь — шашка по квадам.** Полярные треугольники `Alt+J` (Tris to Quads) на веере часто оставляют мусор, шахматка плывёт. Надёжнее накладка:

6. Object Mode, `Add ‣ Mesh ‣ Grid`. Имя `PlazaPaving`. Size 2800. Vertices X и Y = 9 (8×8 квадов) или 11 (10×10). `Ctrl+A` ‣ Scale. Поставить на пол площади (z ≈ −180 после I1), поднять на +0.4 м против z-fight.
7. Тот же материал `IslandVertex`. Тот же Color Attribute `Color`.
8. Edit Mode, Face (`3`). `A` выделить все лица. `Select ‣ Checker Deselect` — останется половина квадов.
9. Vertex Paint (`Ctrl+Tab` ‣ Vertex Paint) **или** остаться в Edit и задать атрибут: в Vertex Paint включить маску лиц (иконка лица в хедере), `Paint ‣ Set Vertex Colors`. Цвет кисти задать **точно**: в Color Picker Hex `A3AEC2`, не крутить HSV на глаз. Затем инвертировать выделение лиц (`Ctrl+I` в Edit Face) и Set Vertex Colors Hex `707B92`.
10. `PlazaPaving` родитель к `Island` (`Ctrl+P` ‣ Object) или `Ctrl+J` влить в `Island`. Если Join — атрибут `Color` не потерять (имена совпали). Экспорт массы включает этот меш.

**Дорожки кольца — покраска существующих треугольников**, не второй материал.

11. Edit Mode на `Island`, Top Ortho (`Numpad 7`, `Numpad 5`). Face select. Выделить кольцо дорожек вокруг площади и к зданиям (круговая полоса; ширина на глаз владельца, не клетка пака). Не красить весь диск одним серым.
12. Vertex Paint + маска лиц ‣ Set Vertex Colors `#707b92` или чередовать два серых, если удастся собрать полосы. Остальной топ кольца и бровка — грунт `#2e3a16`. Утёс не красить в плитку: оставить скальный серо-коричневый из той же палитры (`#5c4426` / `#3a3f4d`).

**Экспорт.** `export_runtime.py` с `export_vertex_color="MATERIAL"`. Проверка GLB: `pnpm exec gltf-transform inspect runtime/island_mass.glb` — у примитива массы есть `COLOR_0`, текстур земли нет (или они не используются). Если `COLOR_0` нет — материал не читает Color Attribute, либо экспортёр в режиме `NONE`.

**Критерий.** В `view.html` на тонком файле двор — шашка, не голая триангуляция; кольцо не одноцветный блин; к стоящим зданиям читаются дорожки. Текстуры мощения нет. Материалов земли не больше одного. Масса ≤ 1.5 МБ.

**Чем проверять.** inspect GLB; вид в смотрелке; Blender Attribute shading.

**Запрещено.** Текстура шашки (PNG/WebP плитки). Второй материал «плитка / трава» на земле. Тайлы легенды пака. Pixelize / 53 цвета как процесс. Вода.

### I3. Декор

Ключ: `island_decor`.

**Цель.** В кадре деревья, фонари, ограждение бровки верхнего яруса, лестницы спуска на площадь. Расстановка авторская, не квота района, не легенда пака (`plant` / `walker`).

**До неё.** I0 (родители `inst_*`, тонкий экспорт), I1 (есть бровка и перепад), I2 (есть дорожки, вдоль которых фонари).

**Бюджет кадра.** Суммарный остаток после зданий — около 100 000 треугольников на мощение, декор, облака и всё остальное вместе; декор обязан идти инстансами.

**Гайд.** Источники мешей — `docs/reports/ASSETS_ISLAND.md`. Не качать «дерево с TurboSquid» мимо списка. Импорт: `File ‣ Import ‣ glTF 2.0`. После импорта — почистить текстуры, перевести на вершинный цвет (тот же приём I2) или один плоский Principled без карт; уложиться в бюджет библиотеки 600 КБ **на все** уникальные меши декора суммарно.

**Обычный vs связанный дубликат.**

- `Shift+D` — новый объект **и** новая копия mesh-data. Сорок деревьев = сорок мешей = сорок вызовов (пока не instance).
- `Alt+D` (`Duplicate Linked`) — новый объект, **те же** данные меша (`ob.data` один, `users ≥ 2`). Это предусловие `EXT_mesh_gpu_instancing`.

Проверка связи: выделить дерево ‣ Properties ‣ Data — имя меша и число users (например `TreeMesh 47`). Либо `Select ‣ Select Linked ‣ Object Data` (`Shift+L` ‣ Object Data): должны подсветиться все копии семейства. Если users = 1 у каждой копии — это были `Shift+D`, инстанса не будет.

**Сборка по семействам (ограничение экспортёра 4.5).**

1. Empty `inst_tree` уже из I0 (если нет — `Add ‣ Empty ‣ Plain Axes`, имя строго `inst_tree`). Дерево-прототип — ребёнок этого Empty: выделить прототип, затем Empty, `Ctrl+P` ‣ Object.
2. Дальнейшие деревья: выделить прототип, `Alt+D`, разместить, проверить что parent всё ещё `inst_tree` (если Blender сбросил — снова `Ctrl+P`). Не давать детям детей.
3. То же для `inst_lamp`, `inst_fence`, `inst_stair`. Лестница — отдельный меш (ступени low-poly), инстансы в местах спуска площади (минимум два противоположных края, лучше четыре стороны прямоугольника). Ограждение — короткие сегменты по бровке **верхнего** яруса (кольцо на z ≈ 0), не по дну утёса.
4. Расстановка: деревья между домами и по бровке; фонари вдоль дорожек I2; не ставить сеткой «N на клин». Юнитов, машин, дронов, человечков — нет.
5. Экспорт: `export_gpu_instances=True`. Страховка после экспорта:
   ```
   pnpm exec gltf-transform inspect runtime/island_mass.glb
   ```
   В JSON/inspect должно быть `EXT_mesh_gpu_instancing` на узле `inst_tree` (и прочих). Если нет — `pnpm exec gltf-transform instance runtime/island_mass.glb runtime/island_mass.glb` (сворачивает дубликаты mesh-data в инстансы). Почему сначала Blender-parent, потом CLI: CLI — сеть; авторская иерархия нужна, чтобы не разъехались трансформы.
6. Не запускать `build_island.py`.

**Критерий.** В тонкой смотрелке видны деревья, фонари, ограждение, лестницы. Уникальных мешей декора — единицы; копий — десятки. Вызовов на сорок деревьев — один (inspect / в I7 — `InstancedMesh` / GPU instancing). Библиотека (уникальные меши декора в mass+отдельных файлах, если вынесены) ≤ 600 КБ. Масса с декором ≤ 1.5 МБ.

**Чем проверять.** `Shift+L` Object Data в Blender; inspect GLB на `EXT_mesh_gpu_instancing`; вид; размеры.

**Запрещено.** `Shift+D` как основной метод. Квота «минимум N деревьев на район». Walker/vehicle/drone. Вода. Второй атлас «декор пака». `packages/render`.

   - Shader 2: Emission тот же (для непрозрачных облаков оба входа Emission; Principled не ставить);
   - Mix Shader → Material Output.
7. Часть облаков: `G Z` вниз, **ниже** низа острова (утёс до ≈ −2517 — облака на z ≈ −800…−1800 читаются «под островом», не внутри камня). Часть — вокруг и чуть выше топа. Инстансы: parent `inst_cloud`, `Alt+D`.

Вариант А (предпочтителен, меш в сцене): большая сфера `SkyDome`, Scale ~30000, нормали внутрь (`Alt+N` ‣ Flip), вершинный цвет градиента `#6fb4f0` / `#aadcff` (рампа `blue`), материал unlit как у облаков. **Критерий.** В тонкой смотрелке: голубое небо-меш или эквивалент не-заливки; белые куски облаков, хотя бы два ниже острова; на фасадах читаются тёплые окна и цветной неон вывесок без 18 emission-текстур. Цикла дня/ночи в смотрелке нет.
