# TZ_HUD — интерфейс Corporator

Каркас HTML/CSS. **После** принятого вида острова (`PLAN_ISLAND.md`). Этапы V8/V9 из `PLAN_VISUAL.md` — архив, не старт острова.
Канон — `HUD.md` и `docs/SCREENS.md`. Мокап — `docs/mockups/hud_mockup_v1.png`.
Числа геометрии — `content/fixtures/hud_layout.json`. Тексты — `content/strings/ru.json`.

> **Восстановлено 2026-09-01** из ТЗ до пивота 31 августа (`R-V-55`). Баннер «стройка
> снята / BUILD = стейк» снят. Экран `build` снова каталог и посадка с клика по тайлу.
> Миссии **не** оживают: `missions_live=0`, пункт-заглушка (`R-V-4`). Лейаут острова
> один на всех (`R-V-15`): схема районов из `derived`, не «при смене сида».

Задача не «сверстать красиво», а достичь плотности мокапа при том, что **60% экрана арта
не требует**: это HTML поверх канваса. Сегодня `apps/client/src/hud/App.tsx` — скелет на
215 строк с `data-key` атрибутами и без единой панели в человеческом виде.

## §1. Что на мокапе и чего в нём не надо повторять

`hud_mockup_v1.png` собран по спеке `HUD.md`. На кадре старый растровый логотип
`AI CITY` и тикер `$CITY` — **это не канон**. Канон: `CORPORATOR` и `$CORP`. Подписи
нижнего меню на мокапе — заглушки генератора картинки; всё меню будет HTML, а не спрайты.

Смотреть на мокапе нужно на две вещи: **состав панелей** и **плотность**. Копировать
пиксели не нужно и вредно.

Пять отличий от мокапа, которые уже приняты каноном `HUD.md` §1 и обязательны:

1. Главное число топбара — **Capital**, не `$CORP`.
2. Рядом с часами — **плашка банка**: открыт до / закрыт, откроется через / воскресенье.
3. В `OVERVIEW` — строка **Payroll**, видимая только при урезании фонда.
4. В сток-баре — **два числа** на сток: рынок и эффект в игре.
5. Чат и карта мира убраны, их слоты заняты панелью районов и обзором районов.

## §2. Сетка и геометрия

Числа — только из `content/fixtures/hud_layout.json`, ни одного `px`-литерала в CSS вне
блока токенов (`L341`).

```
aspect 16:9 · колонки 260px · топбар 56px · сток-полоса 40px · нижнее меню 48px
```

Реализация — CSS Grid, значения приходят в CSS-переменные из фикстуры на монтировании:

```
--hud-col:   260px
--hud-top:    56px
--hud-strip:  40px
--hud-menu:   48px
```

```
grid-template-columns: var(--hud-col) 1fr var(--hud-col);
grid-template-rows:    var(--hud-top) 1fr var(--hud-strip) var(--hud-menu);
```

Канвас сцены лежит абсолютно на всю область, панели — поверх, с полупрозрачной
подложкой. Безопасный прямоугольник камеры (`504×432` при базовом вьюпорте) вычисляется
формулой `safeRect` из `apps/client/src/layout.ts` и уже реализован — не дублировать.

**Адаптив.** Ниже ширины, при которой центр становится уже безопасного прямоугольника,
колонки сворачиваются в выдвижные панели по кнопке. Порог — ключ пака
`render.hud_narrow_threshold_px`, не медиазапрос с литералом. Топбар, сток-полоса и
нижнее меню не сворачиваются никогда: там живут четыре несрезаемых места.

## §3. Токены

Палитра HUD — та же, что у спрайтов, чтобы интерфейс и сцена были одним произведением.
Источник — `art/palette/corporator.hex`, сверка хеша с `render.palette_sha256`.

Токены заданы `HUD.md` §7 и не изобретаются заново:

```
--bg-panel      navy   1b2436 @ 92%
--bg-panel-hi   navy   24314a
--stroke        navy   3b4f73
--text          concrete c2cbdb
--text-dim      concrete 707b92
--accent-ai     green  2fa348      NVDA, compute
--accent-energy crimson c9333c     TSLA, energy
--accent-logi   amber  e8a52c      AMZN, logistics
--accent-cons   highlight e6ecf5 + amber ffc857   AAPL, consumer
--accent-auto   navy   4a648c      MSFT, automation
--accent-fin    blue   3f86d1      COIN, finance
--good          green  5fd167
--bad           crimson e85561
--warn          amber  ffc857
```

Панель: рамка 1px `--stroke`, скругление **2px максимум** — больше выпадает из пиксельной
сетки. Подложка прозрачная, чтобы сцена читалась.

Шрифт: пиксельный битмап для чисел и заголовков, обычный sans для длинных строк лога.
Полностью пиксельный лог нечитаем — это прямой запрет `HUD.md` §7. Файл шрифта —
вендоренный woff2-сабсет из `art/fonts/` (`TZ_ART.md` §5), без сетевых запросов (`L344`).

Никаких CSS-фреймворков. Один файл `apps/client/src/hud/hud.css`: блок токенов, затем
классы по компонентам. CSS-in-JS не вводится: он раздувает бандл и мешает измерять его
потолок.

## §4. Топбар

Единственный элемент, который виден всегда и никогда не скроллится. Порядок слотов
неслучаен: что тратишь → что ограничивает → когда это можно сделать.

| слот | содержимое | источник | поведение |
|---|---|---|---|
| лого + уровень | `CORPORATOR` · `LV 27`, XP `8450 / 12000` | server | полоса XP; уровень гейтит слоты застройки |
| **CAPITAL** | SI-суффикс, три значащих (`22.3M`) + дельта за сутки города | server | главное число, крупный кегль, анимация при начислении |
| `$CORP` | баланс кошелька | server | клик → банк; серым без кошелька |
| ENERGY | число + баланс потребления | server | красный, если потребление > производства |
| COMPUTE | число | server | серый, если район NVDA не открыт |
| POPULATION | число + прирост | server | |
| **DAY / ЧАСЫ** | `DAY 148 · ПН 12:45` + иконка дня/ночи | client_clock | личные часы города |
| **БАНК** | `ОТКРЫТ до 20:00` / `ЗАКРЫТ, откроется через 3:12` / `ВОСКРЕСЕНЬЕ` | client_clock | плашка: зелёная / серая / янтарная |
| меню | shop, inventory, mail, tasks, настройки | server | бейджи непрочитанного |

Формат чисел: Capital, GDP и Treasury — целые. При значении ≥ 10 000 — SI-суффикс и три
значащих цифры, точное целое в тултипе. Без этого топбар с `workshop_cost_l1` в десятках
миллионов не читается.

Часы и плашка банка обновляются раз в секунду локально по формуле
`city_time = anchor + (now − first_login) × rate` (`clock.ts`), без запроса к серверу.
Всё остальное — по событию тика.

**Плашка банка не срезается ни при каких условиях** (`L342`). Проба
`bank_plaque_always_present` обязана падать при её отсутствии.

## §5. Левая колонка

### 5.1. `OVERVIEW`

| строка | формат | примечание |
|---|---|---|
| GDP / день | `14.2M` + спарклайн за 7 суток города | Capital за сутки |
| Productivity | `82%` | измерение выхода, не второй множитель |
| Happiness | `76%` | ниже `happiness_penalty_threshold_bps` — строка краснеет |
| Stability | `68%` | ниже `stability_hint_threshold_bps` — подсказка «проверь energy» |
| **Payroll** | `84%` | при 100% **не показывается вовсе** |
| Treasury | `2.34M` | Capital города, не `$CORP` vault и не фонд |

Строка Payroll — самая важная новая строка. При `< 100%` показывается с подсказкой «фонд
зарплат тонкий, выплаты урезаны пропорционально у всех». Молча урезать нельзя (`L342`,
проба `payroll_row_appears_when_trimmed`).

Спарклайн — 7 точек, ступенчатая ломаная в один цвет, без сглаживания. `HUD.md` §9
разрешает срезать спарклайн до одной цифры; в этой фазе он рисуется, потому что фаза
именно про картинку.

### 5.2. `ACTIVE EVENTS`

Максимум 3 строки плюс `VIEW ALL`. Тип, название, обратный отсчёт в часах города, иконка.
Отсчёт — `client_clock`, не сервер.

### 5.3. `DISTRICTS`

Шесть строк, по одной на сток. Заняла слот чата.

```
NVDA  AI / Compute      ОТКРЫТ      Compute      +6.2%
TSLA  Energy            ОТКРЫТ      Energy       −2.1%
AAPL  Consumer          ОТКРЫТ      Happiness    +4.0%
AMZN  Logistics         ЗАКРЫТ      4 AMZN · ~2 400 CORP
MSFT  Automation        ЗАКРЫТ      6 MSFT · ~2 400 CORP
COIN  Finance           ЗАМЕРЗАЕТ через 21:40
```

Пять состояний, каждое своим токеном цвета: `ЗАКРЫТ` (порог в токенах и цена открытия в
CORP), `ОТКРЫТ` (с efficiency), `ЗАМЕРЗАЕТ` (анстейк, отсрочка), `ЗАМОРОЖЕН`, `STALE`
(оракул устарел). Клик по закрытому ведёт в `exchange`.

Цвет строки — акцентная рампа района из §3, чтобы связь с районом на сцене была
мгновенной.

## §6. Правая колонка

### 6.1. Карточка города

Имя, ID, ранг в лидерборде. Ниже: Treasury (Capital), `$CORP` в кошельке, стоимость
стейка (справочно, это не игровые деньги).

**Отдельная плашка протокола**, не смешанная с Treasury: ETH в пути, `$CORP` фонда и
vault, стоки котлов `farm` и `month`, ETH студии. Кнопок слива и паузы на ней нет. Не
писать «залочено навсегда». После аварии — цифра и Payroll, не «овнер вывел»
(`.cursor/rules/hud.mdc`, Rev-A).

### 6.2. `AI AGENTS`

`12 / 20` — занято из лимита. Три состояния, и все три различимы с одного взгляда:

```
#71  Chief Engineer   LV 23   ● Работает    Robotics Lab
#32  Chief Trader     LV 21   ● Работает    Bank
#54  Researcher       LV 19   ○ Простой     нет compute
#91  Logistics AI     LV 18   ◐ Урезан 84%  Logistics Hub
```

**Причина простоя обязательна** (`L342`): `нет compute`, а не пустой статус. Текст
причины — из кода `IDLE_*` через `ru.json`, не сочиняется в компоненте.

Клик по строке → `agent_card`.

### 6.3. `LOG`

Лента событий по времени города. Вкладка `AGENT LOG` в v1 срезана (`HUD.md` §9) — но
фильтры остаются: `все`, `COMPANION_`, `выплаты`, `отказы`.

```
12:43  Agent #71 расширил Robotics Lab до LV 3
12:41  Agent #32 смена в банке        +140 Capital  ✓ Verified
12:38  Energy Plant                   +2 500 Energy
12:35  Agent #54 простой              нет compute
```

Бейдж: `· logged` до включения живого merkle-слоя, `✓ Verified` после (V11). Клик по
бейджу открывает proof и CID. Бейдж `Verified` без корня и CID — ловится `L350`.

Строка `MODIFIER_CAP_CLAMPED` с именем ключа выводится отдельно: молча урезать выход
нельзя (`DESIGN.md` §5.3).

Клиент считает выход смены в **BigInt**: худший числитель сплава длиннее 53 бит, `Number`
теряет точность. Это уже учтено в `values.ts` — не ломать.

### 6.4. `DISTRICT OVERVIEW`

Заняла слот карты мира. Мини-схема острова: шесть зон, залитые акцентным цветом района,
серые пока закрыты, с точкой заполненности. Клик по зоне → камера в
`derived.zone_centroids` (`TZ_RENDER.md` §7.3).

Схема рисуется из `derived.zone_centroids` и `zone_block_counts`, не картинкой: иначе она
разойдётся с запечённой сценой (лейаут один на всех, `R-V-15`).

## §7. Центр

### 7.1. Сцена

Хост канваса. Панели съедают события указателя: канвас получает `pointerdown` только если
цель события — сам канвас (атака `A-V-11`).

### 7.2. `STOCK MARKET` — сток-полоса

Ключевое отличие от мокапа: **два числа на сток**. Шесть колонок не влезают в строку
честно — полоса скроллится по горизонтали, видны 4, остальные доезжают.

```
NVDA          TSLA          AAPL          AMZN     →
$184.20       $171.35       $189.40       $153.78
+4.12%        −2.45%        +1.10%        +1.65%
Compute       Energy        Happiness     Logistics
+6.2%         −2.1%         +4.0%         закрыт
```

Верхние два числа — рынок. Нижние — эффект в игре. Они **не совпадают и не должны**:
efficiency считается по отношению EMA с лагом в сутки и зажата в ±15%. Тултип объясняет
это одной фразой, иначе игрок решит, что мы врём в числах.

Полоса — рынок и эффект, не магазин. Купить сток — в `DISTRICTS` / `exchange`, только за
`$CORP`. Не шесть пар `CORP/сток`: hop `CORP → ETH → USDG → сток` под капотом.

Проба `stock_bar_shows_two_numbers` обязана падать, если строк чисел меньше двух.

### 7.3. Нижнее меню

`BUILD` · `AGENTS` · `DISTRICTS` · `RESEARCH` · `BANK` · `MISSIONS` · `LEADERBOARD`

Семь пунктов в одну строку высотой 48px. Состав — из `screens.json`, где
`screen == "bottom_menu"`, не из литерала в компоненте.

`BANK` подсвечивается, когда банк открыт и есть что выводить. `DISTRICTS` — когда порог
стейка достигнут, но район не открыт. `MISSIONS` остаётся заглушкой и несёт
`FEATURE_NOT_IN_V1`: миссий в фазе нет (R-V-4, `L347`). Пункт не удаляется — семь пунктов
меню не меняются.

## §8. Экраны — этап V9

Пятнадцать экранов `kind=screen` и одиннадцать панелей `kind=panel`. Инвентарь — пак,
матрица «экран × элемент × коды» — GENERATED «T9: элементы и отказы». Компонент на каждый
экран пака и экран пака на каждый компонент (`L358`).

### 8.1. Пять законов экрана — исполняются буквально

Из `docs/SCREENS.md` §1:

**A. Отказ выводится, а не пишется.** У элемента список токенов `requires`, не рукописный
список кодов. Компонент получает вычисленный отказ, а не вычисляет его сам.

**B. На кнопке один блокирующий код, остальные — в тултипе.** Порядок тотальный
`(tier, token)`, блокирующий — первый упавший. Проба `refusal_shows_one_blocking_code`.

**C. Порядок гейтов — от постоянного к сиюминутному.** Identity → scope → unlock → slot →
funds → window → limit → external. Внутри identity: демо, затем кошелёк, затем чужая сеть.
«Не хватает Capital» на закрытом районе — дефект доверия.

**D. Число либо выводится из пака, либо приходит живым состоянием, либо считается
клиентом из часов и формата. Фикция запрещена.**

**E. Клиент не считает экономику.** Экономические `kind` — только `server`.

### 8.2. Экраны

| экран | что делает | обязательные отказы |
|---|---|---|
| `build` | каталог и посадка; тайл — из клика по сцене | `CITY_LEVEL_TOO_LOW`, `BUILD_TILE_ILLEGAL`, `NO_FREE_BUILD_SLOT`, `NOT_ENOUGH_CAPITAL` |
| `agents` | найм и список | `NO_FREE_AGENT_SLOT`, `NOT_ENOUGH_CAPITAL` |
| `districts` | шесть строк, открытие за `$CORP` | `WALLET_NOT_CONNECTED`, `STAKE_BELOW_THRESHOLD`, `NOT_ENOUGH_CORP`, `DISTRICT_LOCKED` |
| `exchange` | покупка стока; итог в Capital, **не маршрут** | `WALLET_NOT_CONNECTED`, `NOT_ENOUGH_CORP`, `EXCHANGE_HOP_UNAVAILABLE` |
| `bank` | депозит и вывод; живой лимит и курс минта | `DEMO_NO_WITHDRAW`, `WALLET_NOT_CONNECTED`, `NOT_ENOUGH_CAPITAL`, `BANK_CLOSED`, `BANK_SUNDAY`, `BANK_DAILY_LIMIT_REACHED` |
| `research` | узлы из осей `research.json` | `CITY_LEVEL_TOO_LOW`, `NOT_ENOUGH_CAPITAL` |
| `missions` | остаётся заглушкой: пустота `no_events_yet`, ни одного живого элемента | `FEATURE_NOT_IN_V1` на всех элементах |
| `leaderboard` | ранг Influence, клейм приза | `PRIZE_*`, `WALLET_NOT_CONNECTED` |
| `building_card` | уровень, апгрейд, клип `MODIFIER_CAP_CLAMPED` | `NOT_ENOUGH_CAPITAL` |
| `agent_card` | история и причина простоя | `IDLE_OUT_OF_HOURS` как предупреждение |
| `district_card` | дерево узлов тира и клейм фрагментов | `TIER_NOT_UNLOCKED`, `STAKE_MULT_SHORT`, `NODE_SIDE_LOCKED`, `MERGE_MATCHING_BLOCKED`, `DEMO_NO_CLAIM` |
| `offline_return` | сколько тиков догнано, не больше капа | `IDLE_OFFLINE_CAP_REACHED` |
| `onboarding_demo` | шесть шагов, §8.4 | `DEMO_NO_WITHDRAW` на финале |
| `wallet_connect` | четыре состояния кошелька | `WALLET_NOT_CONNECTED`, `WALLET_WRONG_CHAIN` |
| `settings` | язык, звук, точные числа, анимация тика, тумблер автопилота | — |
| `companion` | новый экран, V10, `TZ_FEATURES.md` §2 | `DEMO_NO_COMPANION`, `COMPANION_*` |

`exchange`: поля `kind=route` нет. Витрина показывает интервал итога в Capital
(`exchange_quote_capital_bps`): vault, иммутабельный `creatorTaxBps`, лишняя нога как
интервал. Неоценённая нога — `EXCHANGE_HOP_UNAVAILABLE`, маршрут не подставляется
(`L157`).

`bank`: спот пула `CORP/ETH` на полях банка запрещён (`L156`). Курс минта —
`generated.economy.anchor_mint_rate`, коды `MINT_RATE_CAPPED` и `STALE_PRICE`. Живой
дневной лимит — свидетель `bank_daily_limit_live`; если связала глубина —
`BANK_LIMIT_FROM_DEPTH` рядом с причиной.

### 8.3. Пустота и загрузка

У каждого экрана есть `loading_kind` и пустота (`empty_kind` или `empty_code`).
**Молчаливого нуля нет** (`L145`, проба `every_screen_has_empty_and_loading`).

Виды загрузки: `skeleton` (каталог, списки), `spinner_inline` (подключение кошелька, без
смены числа), `stale_freeze` (банк и биржа: старое число замораживается и помечается, а
не обнуляется).

### 8.4. Онбординг демо

Порядок шести шагов задан `docs/SCREENS.md` §6 и не переставляется: город и часы →
посадка Engineer в Workshop → валидный тик с выплатой → искусственный простой
`IDLE_NO_ENERGY` → плашка банка и его часы → предложение кошелька с `DEMO_NO_WITHDRAW`.

Причина порядка: игрок видит **причину простоя** раньше, чем впервые захочет вывести
деньги.

Демо изолирован: нет `wallet`, нет `corp`, нет `spend ≠ none`, нет компаньона, нет приза,
нет фарма, `demo_transfer_edges` пуст. Барьер демо не ослабляется ни на пиксель.

## §9. Тексты и локализация

Кириллица интерфейса живёт **только** в `content/strings/ru.json`. В компонентах и в CSS
кириллицы нет ни одной (`L343`, проба `no_cyrillic_in_components`). В `screens.json`
кириллица допустима только в поле `why` (`L146`).

Компонент получает ключ строки и подставляет параметры. Новый текст — сначала ключ в
`ru.json`, потом использование. Обратный порядок ловится линтером.

Вторая локализация — вне фазы. Но структура ключей не должна ей мешать: ни склеивания
строк в коде, ни зависимости от порядка слов.

## §10. Частоты обновления

| что | как часто |
|---|---|
| часы города, плашка банка, таймеры событий | 1 с, локально по формуле, без запроса |
| Capital, Energy, Compute | по событию тика |
| лог, статусы агентов | по событию тика |
| GDP, Productivity, Happiness, Stability, Payroll | раз в тик, агрегатом |
| цены стоков | период сэмплера, не реже минуты |
| efficiency районов | раз в сутки города (06:00) плюс на входе |

**Транспорт события тика.** Сегодня клиент не открывает WebSocket: греп `WebSocket` по
`apps/client/src` даёт ноль, обновление идёт повторным `GET /city/{city_id}/state` после
команды. Шаблон и сервер готовы: `packages/protocol/src/listen.ts` даёт
`wsTemplate = "/city/{city_id}/ws"` и `wsHeartbeatMs = 15000`, `services/api/src/listen.ts`
уже делает upgrade и пульс. В V8 клиент открывает WS и обновляет HUD по кадру пульса;
при обрыве — переподключение и деградация на поллинг, с видимым индикатором, а не молча.

Клиент **не** считает экономику. Он отображает присланное и локально экстраполирует
только часы. Boot без `city_time` сервера — код отказа, не пустые нули.

## §11. Структура кода

```
apps/client/src/hud/
  App.tsx            только сетка и композиция, без бизнес-логики
  hud.css            токены и классы
  topbar/            Topbar.tsx, CapitalSlot.tsx, BankPlaque.tsx, ClockSlot.tsx
  left/              Overview.tsx, Sparkline.tsx, ActiveEvents.tsx, DistrictsPanel.tsx
  right/             CityCard.tsx, ProtocolPlaque.tsx, AgentsPanel.tsx, LogPanel.tsx,
                     DistrictOverview.tsx
  center/            SceneHost.tsx, StockBar.tsx, BottomMenu.tsx
  screens/           по файлу на экран из §8.2
  parts/             Panel.tsx, Value.tsx, Badge.tsx, Refusal.tsx, Empty.tsx, Loading.tsx
  model.ts           преобразование снапшота в вид, уже существует — расширяется
```

Дисциплина: TypeScript strict, `any` запрещён, `!` запрещён, `readonly` по умолчанию,
исчерпывающий `switch` с never-guard. Файл длиннее ~400 строк делится. Числовые литералы
в компонентах — только `0`, `1` и индексы; всё остальное через токены и пак.

`parts/Refusal.tsx` — единственное место, которое рендерит отказ: один блокирующий код
крупно, остальные в тултипе. Ни один экран не собирает текст отказа сам.

`parts/Value.tsx` — единственное место, которое форматирует число: SI-суффикс, три
значащих, точное целое в тултип, BigInt внутри. Ни один экран не форматирует сам.

## §12. Приёмка

### V8 — каркас

1. Геометрия совпадает с фикстурой: колонки 260, топбар 56, полоса 40, меню 48. Ни одного
   `px`-литерала в CSS вне блока токенов.
2. Плашка банка показывает три разных текста в трёх состояниях (открыт, закрыт с
   отсчётом, воскресенье).
3. Строка Payroll появляется при `payroll_ratio < 100%` и исчезает при 100%.
4. Причина простоя видна в каждой строке простаивающего агента.
5. Сток-бар показывает две строки чисел на каждый сток и скроллится горизонтально.
6. Ни одной кириллической строки в `.tsx` и `.css`.
7. Шрифт вендорен, лицензия рядом, ни одного сетевого запроса за шрифтом.
8. Бандл JS под `arch.params.client_bundle_max_bytes`.
9. Визуально: скриншот HUD рядом с мокапом — состав панелей совпадает, плотность
   сопоставима.

### V9 — экраны

1. Каждому экрану пака соответствует компонент и наоборот.
2. У каждого экрана есть пустота и загрузка; молчаливого нуля нет.
3. На кнопке вывода без кошелька виден `WALLET_NOT_CONNECTED`, а не «не хватает Capital».
4. Демо-поток проходит шесть шагов онбординга в заданном порядке.
5. Демо не получает компаньона, приза и фарма; коды `DEMO_NO_*` идут раньше остальных.
6. На бирже нет поля маршрута; итог показан интервалом в Capital.
7. В банке нет спота пула; курс минта — из `anchor_mint_rate`.

Слова «выглядит нормально» приёмкой не считаются: каждый пункт закрывается тестом или
скриншотом с указанием, что на нём проверяется.
