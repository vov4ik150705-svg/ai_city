# TZ_BUYBACK — котлы Farm и месяца из оборота пула

Живое ТЗ. Задание — чтобы котлы `PrizeTreasury` наполнялись **купленным** стоком из сбора с оборота `CORP/ETH`, а не из мока и не из допечатки.

Сейчас `createDefaultConveyorSubmit` всегда ставит `createMockConveyorSource()`. Его `pull()` возвращает `SERVICE_DEGRADED` и пустое тело. `createBuybackPort` на заполненном RPC умеет стать живым, но порт без батча ничего не кладёт в котёл. Запуск токена это не включает: после `launchToken` источник останется моком, пока этот файл не исполнен.

`docs/reports/TZ_WITHDRAW.md` это не делает (§8). Задачи `X0`…`X15` не переоткрывать. Нарезка Farm остаётся в API (`sliceFarm`). Конвейер по-прежнему отклоняет срез котла FARM.

Читать целиком §0 и §1 до первой правки. Дальше — только ту задачу, которую закрываешь. Как исполнять — `.cursor/rules/tz-buyback.mdc`.

## 1. Что уже есть и чего нет

### 1.1 Уже есть

- Сэмплер вне тика пишет `dex_turnover_usd_8dec` в `price_samples`. Тишина фида даёт оборот 0 и `feedLive` 0. Это наблюдение, не батч.
- `runStockConveyor` при `hopOk`, живом `buybackExecutorService` и `fill > 0` зовёт `prizeTreasury.deposit` в котёл MONTH (`1`) и котёл FARM (`0`). Срез с `kettle === PRIZE_KETTLE_FARM` отклоняется. Срезы месяца конвейер проводит, если `callerService` — `voucherService` пака.
- `sliceFarm` в API режет котёл 0 по `fragment_owed` и пишет `FRAGMENT_POOL_EMPTY`, когда сумма бумажного долга больше ненарезанного мешка. `Σ > bag` не режется.
- `claim_fragment` при долге города и нулевом `owed` сети отвечает `FRAGMENT_SLICE_PENDING`. Месяц при всех нулях — `PRIZE_NOTHING_OWED`. Демо и пустой `launch.deployed` — `DEMO_NO_PRIZE`.
- Игрокский хоп уже описан в `commit_exchange.ts`: POST JSON `ticker`, `amount`, `hop_quality`, опционально `want: "tx"`, `recipient`. Ответ `stock_out`, для tx ещё `to`, `data`, `value`. Нет URL, не-ok или нет полей — это не филл. Покупка игрока признаётся только по логу `Transfer` на кошелёк.

### 1.2 Дыра

Никто не собирает батч. `pull()` без аргументов вызывается только если HTTP-тело **не** разобралось как батч. `startMain` слушает мок-источник. Пустой POST — деградация, и это правильно для «нечего класть». После запуска пула это останется деградацией, пока не появится сборщик.

`planFarmHops` без `fragmentDemand` не покупает Farm, даже если `farmWei > 0`. Спрос лежит в состоянии API, не в процессе байбека.

### 1.3 Как должно работать

Вне тика, раз в `buyback_cadence_city_hours`:

1. API читает последний живой `price_samples`. `feedLive` 0 или нет строки — POST не слать, байбек не выдумывает оборот.
2. API считает доли тем же делением, что пак (`fee_split` от оборота): `fundWei`, `leaderboardWei`, `farmWei`. Считает `fragmentDemand` как сумму `fragment_owed` по тикеру по городам. Кладёт срезы месяца только из уже посчитанного сезонного долга, с `caller` = `voucherService`. Филлов в этом POST нет.
3. Байбек на этом теле (это не полный батч) сам спрашивает хоп. `recipient` — адрес `buyback_executor`. Подписывает swap ключом исполнителя, не ключом игрока. В `farmFills` / `monthFills` пишет `stock_out` только после лога `Transfer` на исполнителя.
4. Дальше тот же `runStockConveyor`. Потом существующий `sliceFarm` режет FARM. `claim_fragment` и `claim_prize` начинают видеть `owed > 0` только после депозита и нарезки.
5. Хоп молчит, квитанции нет, оборот ниже `buyback_min_batch_wei`, спрос Farm нулевой — депозита нет. Коды игрока те же, что сейчас. Это честный пустой котёл, не мок.

Пока пула нет, шаг 1 не находит живой оборот. Код от этого не включается «на глаз» и не минтит сток.

## 2. Решения

- **R-B-01.** Мок-источник остаётся дефолтом `createDefaultConveyorSubmit` и ответом на пустое тело. Живой сборщик включается в `startMain`, когда заданы RPC-переменные байбека и `CORPORATOR_HOP_URL`. Нет переменных — процесс как сейчас.
- **R-B-02.** Филл без лога `Transfer` на `buyback_executor` не существует. Газ swap платит исполнитель байбека. Газ `claim_fragment` / `claim_prize` / `present` по-прежнему платит игрок.
- **R-B-03.** FARM режет только `sliceFarm`. Конвейер кладёт сток в котёл 0 и срезы FARM по-прежнему отвергает.
- **R-B-04.** Месяц: депозит в котёл 1 из `monthFills`; срез — строки сезона в том же прогоне, caller `voucherService`. Нет долга сезона — не резать в никуда. `owed` месяца остаётся 0, пока среза нет.
- **R-B-05.** Спрос и оборот приходят с API по HTTP. Байбек не читает таблицы городов и не импортирует `services/api` и `services/sampler`.
- **R-B-06.** Запуск токена этим ТЗ не делается. Кнопка `claim_prize` не включается. Пустой котёл до первого настоящего swap — ожидаемое состояние, не баг сборщика.

## 3. Задачи

### B0 — красный снимок дыры

Без смены поведения.

- Тест: `createDefaultConveyorSubmit` на пустое тело даёт `ok: 0` и `SERVICE_DEGRADED`, депозита нет.
- Тест: тот же submit с телом `createCannedConveyorSource`-батча, где `hopOk = 1`, филл > 0 и caller — executor, увеличивает `unsliced` котла. Это доказывает, что конвейер живой, а дыра в том, кто подаёт батч.
- Снять заново числа §0.7. Расхождение с снимком записать в отчёте, пак не двигать.

### B1 — доли без сети

Чистая функция в `services/buyback`: оборот и bps пака → `fundWei`, `leaderboardWei`, `farmWei`, остаток студии. Порядок деления один, тот же что у уже существующего `splitCollected` / `fee_split`. Литералов долей в функции нет: bps — аргументы.

Красный тест на паке 189: 10_000 единиц оборота дают fund 100, leaderboard 20, farm 60, studio 20. Ноль оборота даёт нули. Подмена `farm_bps` в тесте меняет только ферму. Функция не пишет порт.

### B2 — хоп и квитанция

В байбеке клиент хопа той же формы, что `hopFillFromEnv` / `hopTxFromEnv`. `recipient` — executor. Разбор квитанции — тот же смысл, что у покупки игрока: лог `Transfer` токена тикера на executor. Тему события не писать одним литералом `0x` + 64 hex (`L314`): резать строку, как в `w12` / `x10`.

Красный тест на заглушке: ответ хопа без последующего лога не становится fill. Лог на другой адрес не становится fill. Молчание хопа — не fill и не исключение наружу, а `hopOk = 0`.

Ключ исполнителя подписывает только swap этого шага. Ключа игрока здесь нет.

### B3 — сборщик в `startMain`

Новый источник: на теле, которое **не** полный батч, но содержит доли B1, спрос и глубины, исполняет B2 и зовёт `runStockConveyor`. Пустое тело — прежний `SERVICE_DEGRADED` (R-B-01). Полный батч, как сейчас, разбирается `parseBatch` и в источник не идёт: тесты с каноническим батчем не ломаются.

`startMain` выбирает этот источник только при полном env RPC и `CORPORATOR_HOP_URL`. Иначе мок. `createDefaultConveyorSubmit` не переключать.

Красный тест: env есть, хоп-заглушка вернула лог, спрос по NVDA > 0, оборот выше минимума пака → `deposit` котла 0 на сумму лога и ни на единицу больше. Спрос всех тикеров 0 → депозита Farm нет, wei остаётся в carry. Оборот ниже `buyback_min_batch_wei` → хоп не вызывается.

### B4 — кадр API

Вне тика, не под локом БД на время сети. Чтение снимка цены и `fragment_owed` — до лока. POST на `listenPorts.buyback` — после. Тик этот POST не ждёт.

Тело — доли, спрос, глубины, срезы месяца. Филлов нет. Нет живого сэмпла — POST нет. Каденция — `buyback_cadence_city_hours`, не новый литерал.

Красный тест: город с `fragment_owed` NVDA и живым сэмплом даёт POST, в котором ферма совпала с B1, спрос совпал с суммой долга, филлов нет. Мёртвый фид — ноль POST. Повтор кадра в тот же час города не шлёт второй POST.

### B5 — приёмка на фикстуре

Один тест, не неделя тиков:

- живой сэмпл с оборотом выше минимума;
- хоп-заглушка с логом `Transfer` на executor;
- POST кадра B4;
- `unsliced` FARM вырос на `stock_out`;
- `sliceFarm` на этом мешке ставит `owed` кошельку;
- месяц: строка сезона в том же прогоне ставит `owed` котла 1, без строки `owed` месяца остаётся 0;
- хоп без лога — котлы не выросли, коды `FRAGMENT_SLICE_PENDING` / `PRIZE_NOTHING_OWED` на пустом долге сети те же;
- демо `claim_prize` по-прежнему `DEMO_NO_PRIZE`;
- на каждом шаге `assertI1`, Capital не вырос от депозита стока.

### B6 — канон и гейт

Одно-два предложения в `DESIGN.md`: котлы наполняет сборщик вне тика из оборота и лога хопа; мок остаётся, когда env нет. `docs/API.md` — что пустой POST байбека по-прежнему деградация, а кадр со спросом запускает хоп. В `docs/CANON.md` снять «в коде ещё нет» у решений §2 этого файла, когда B5 зелёный.

Полный `python content/attack.py --jobs 8` и узкий набор тестов байбека, API (`w25`, `h2`, `m4`, новый файл B5). `m4` 20 ≠ 30 не чинить. `launchToken` не подписывать.

## 5. Атаки

1. **Принтер.** Филл без лога `Transfer` попал в `deposit`. — B2, B3.
2. **Лог на чужой адрес.** Исполнитель не получатель — филла нет. — B2.
3. **Нулевой спрос.** `farmWei > 0`, спрос 0, хоп всё равно купил Farm. — B3.
4. **Пыль.** Оборот ниже `buyback_min_batch_wei`, хоп вызван. — B3.
5. **Молчание.** Хоп или RPC молчит, а батч записан с нулями как будто оборот был 0. Должен быть `SERVICE_DEGRADED` без записи. — B3.
6. **Пустое тело сломано.** `createDefaultConveyorSubmit` на пустом теле перестал деградировать, или `m4` ослаблен. — B3.
7. **Двойной кадр.** Два POST в один час города, два депозита с одного оборота. — B4.
8. **Тик ждёт хоп.** Сетевой вызов внутри тика или под локом БД. — B4.
9. **FARM нарезан конвейером.** В теле среза котла 0, конвейер его принял. — B3, регресс X11.
10. **Месяц в никуда.** Срез без сезонного долга увеличил `owed`. — B5.
11. **Касса.** Депозит стока поднял `capital_outstanding` или вызвал `mintFromBacking`. — B5.
12. **Демо.** `claim_prize` демо-города перестал быть `DEMO_NO_PRIZE`. — B5.
13. **Доли мимо пака.** Сумма fund+leaderboard+farm+studio разошлась с `creator_tax_bps` на векторе B1. — B1.
